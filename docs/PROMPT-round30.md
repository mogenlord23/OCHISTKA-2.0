# Задание: круг 30 — движок должен реально работать в той сборке, которую запускает владелец

> Владелец запускает программу из PowerShell и видит: «встроенный движок вирусов в этой сборке
> не работает». Владелец ждёт, что программа будет искать вирусы сразу, без установки.
> **ИИ в этом круге не делаем** — только честный план (T5).

## Что проверено планировщиком (факты, не перепроверять заново)

- `tools/clamav-win/` есть: `bin/libclamav.dll` (24,5 МБ) и `lib/clamav.lib`.
- `crates/platform/build.rs` печатает `cargo:rustc-cfg=clamav_linked` и копирует DLL, когда фича
  `libclamav` включена и папка на месте.
- `apps/desktop/src-tauri/Cargo.toml`: `default = ["libclamav"]`.
- **Но собранный `target/debug/ochistka-desktop.exe` (19:12) не импортирует `libclamav.dll`** —
  проверено `dumpbin /dependents`. Значит эта сборка сделана без движка: build-скрипт не
  применился (устаревший кэш/`Fresh`) либо собиралась другая конфигурация.
- В репозитории уже есть два режима: настоящий движок (`ClamAvEngine`) и «по признакам»
  (`SuspicionEngine`). Второй включается, когда база не загружена.

## Цель

Сборка, которую владелец запускает командой из корня (`npm run dev`) и файлом
`target/debug/ochistka-desktop.exe`, содержит движок: в списке зависимостей exe есть
`libclamav.dll`. Экран «Проверка» при пустой папке баз пишет «Базы не загружены», а не
«движок не собран». Настоящий поиск вирусов включается сам, как только в папке баз появляются
файлы `.cvd`/`.hdb`.

## Этапы

### T1. Найти и устранить причину «движка нет в сборке»

- Воспроизвести: `cargo build -p ochistka-desktop` из корня, затем
  `dumpbin /dependents target\debug\ochistka-desktop.exe` (dumpbin лежит в
  `…\BuildTools\VC\Tools\MSVC\14.44.35207\bin\Hostx64\x64\`).
- Если `libclamav.dll` нет — принудительно перезапустить build-скрипт
  (`cargo clean -p ochistka-platform`), собрать снова и проверить. Зафиксировать в отчёте, что
  именно помогло.
- Сделать так, чтобы это не повторялось: `build.rs` обязан перезапускаться, когда сборка ClamAV
  появляется или меняется. Сейчас `rerun-if-changed` на папку печатается только после того, как
  папка найдена, — поэтому первый билд «запоминает» отсутствие и больше не пересобирается.
  Печатать `cargo:rerun-if-changed` для `tools/clamav-win/VERSION.txt` и `bin` **всегда**, до
  проверки существования, и добавить `cargo:rerun-if-env-changed=CARGO_FEATURE_LIBCLAMAV`.
- Проверка: чистый `cargo build -p ochistka-desktop` (без ручного clean) даёт exe с
  `libclamav.dll` в зависимостях.

### T2. Честный статус в интерфейсе

- Три различимых состояния, простыми словами:
  1. движка нет в сборке → «Проверка вирусов недоступна в этой сборке»;
  2. движок есть, базы нет → «Базы не загружены» + путь к папке + кнопка «Открыть папку баз»;
  3. базы загружены → «База загружена: сигнатур — N».
- Ошибка получения статуса не должна выдаваться за «движка нет» (это уже правилось в `1b5c2f0`;
  проверить, что все ветки так и работают).
- Режим «по признакам» подписывать явно: «Проверка по признакам (без базы)» и показывать это
  рядом с находками. Владелец должен понимать, что это не вирусы.

### T3. Проверить настоящий движок без официальных баз

- Положить в `%LOCALAPPDATA%\OCHISTKA\clamdb` **тестовую** базу `.hdb` с известной сигнатурой
  (сгенерировать скриптом в `tools/` или тестом), перезапустить приложение, убедиться:
  статус «База загружена», проверка папки с образцом даёт находку с этой сигнатурой, чистый файл
  — без находки.
- Это доказывает, что путь «движок → база → находка» работает целиком; официальные базы потом
  просто кладутся в ту же папку.
- После проверки тестовую базу из папки убрать, чтобы владелец не принял её за настоящую.

### T4. Запуск из корня

- `npm run dev` из корня репозитория должен собирать и запускать приложение с движком (проверить,
  что та же команда не подхватывает старый exe и не собирает без фичи).
- В отчёте — точная команда, которой владельцу запускать программу.

### T5. План ИИ (только документ, без кода)

- `docs/status/virus-ai-plan.md`: что значит «ИИ ищет вирусы» на практике, что уже есть
  (эвристика, `NoModel`), что нужно для настоящей модели (набор вирусов и чистых файлов,
  обучение, метрики ложных срабатываний, размер модели, скорость), варианты (готовые открытые
  модели семейства MalConv/EMBER, своя маленькая модель на признаках PE), риски и честные
  обещания. Отдельным пунктом: **нельзя называть эвристику ИИ** и нельзя обещать «ИИ» без
  измеренной точности.
- Никакого кода ИИ в этом круге.

## Не делать

- Не включать перенос в карантин, не менять `disks.rs`.
- Не скачивать официальные базы и не обходить 403.
- Не выдавать «по признакам» за вирусы или за ИИ.
- Не менять экран сверх статусов и подписи режима.

## Критерии готовности

1. `dumpbin /dependents` у свежесобранного exe содержит `libclamav.dll`; повторная сборка без
   `clean` тоже его содержит.
2. Интерфейс различает три состояния из T2.
3. Тестовая база загружается, находка находится, чистый файл чист; после проверки база убрана.
4. Есть точная команда запуска для владельца.
5. `docs/status/virus-ai-plan.md` написан без обещаний, которых нет.
6. Тесты и проверки: `cargo test -p ochistka-platform --features libclamav`, `npm run check`,
   `npm test -- --run src/components/VirusesPage.test.ts`.

## Формат отчёта

Ветка и HEAD, коммиты, отправлено ли; причина, по которой движка не было в сборке (с фактом из
`dumpbin` до и после); что изменено в `build.rs`; PASS/FAIL по критериям; команда запуска для
владельца; что осталось (официальные базы, ИИ по плану, перенос в карантин).
