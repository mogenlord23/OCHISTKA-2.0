## Цель

Приложение собирается с настоящим движком: `clamav_status()` отвечает «доступен», когда база
загружена. База грузится из папки, которую владелец может наполнить сам. Пока базы нет, интерфейс
честно пишет «базы не загружены» и показывает путь к папке. Ничего не удаляется и не переносится.

## Этапы

### T1. Закрепить официальную сборку

- `tools/clamav-win/fetch.ps1`: скачивает `clamav-1.4.6.win.x64.zip` с GitHub Releases по
  закреплённому адресу, проверяет SHA-256 (пин в скрипте), распаковывает в `tools/clamav-win/`
  (каталог в `.gitignore`). Версия — **1.4.6**, потому что FFI сверен с её заголовками.
- Скрипт печатает SHA-256 и версию из `include/clamav-version.h`.
- Если 1.4.6 недоступен — остановиться с понятной ошибкой, не переходить молча на 1.5.5.

### T2. Собрать приложение с движком

- `crates/platform/build.rs`: если существует `tools/clamav-win/`, добавить путь поиска
  `clamav.lib` и скопировать `libclamav.dll` и её DLL-зависимости в каталог выходного бинарника
  (`target/debug`, `target/release`). Без папки сборка не меняется.
- `apps/desktop/src-tauri/Cargo.toml`: фича `libclamav` пробрасывается в `ochistka-platform`.
- Проверка: `cargo build --features libclamav -p ochistka-platform`, затем сборка приложения;
  `clamav_status()` — движок есть, база не загружена.
- Ничего из архива, кроме DLL, в репозиторий не коммитится.

### T3. Базы: папка и загрузка

- Папка баз по умолчанию: `%LOCALAPPDATA%\OCHISTKA\clamdb` (создавать при старте).
- Новая команда `clamav_load_signatures` (путь) + автозагрузка при старте приложения, если в папке
  есть файлы.
- Статус для интерфейса: «базы не загружены» + путь к папке; после загрузки — число сигнатур,
  если libclamav его отдаёт (`cl_load` через `signo`), иначе просто «база загружена».
- Экран «Проверка»: при незагруженной базе — короткая строка и кнопка «Открыть папку баз»
  (`revealInExplorer`). Никаких технических терминов.
- Проверка на пустой папке: понятная причина, приложение не падает.

### T4. Проверка движка без официальных баз

- Тестовая база `.hdb` с сигнатурой EICAR генерируется в тесте во временной папке: загрузить базу,
  отсканировать временный файл — находка с ожидаемой сигнатурой; чистый файл — без находки;
  затем удалить.
- Тест на битую/чужую базу: `cl_load` возвращает ошибку, приложение отвечает понятной причиной.
- Официальные базы (main.cvd/daily.cvd) в тестах не используются: их нет в сети.

## Критерии готовности

1. `fetch.ps1` скачивает и проверяет архив, распаковывает только нужное; повторный запуск не ломает.
2. Приложение собирается с `libclamav`; DLL лежат рядом с `.exe`; без папки сборка не меняется.
3. `clamav_status()` — «база не загружена», после загрузки тестовой базы — «доступен».
4. Сканирование тестовой папки находит EICAR-сигнатуру из тестовой базы; чистый файл — чисто.
5. Экран «Проверка» при пустой папке баз честно пишет «базы не загружены» и открывает папку.
6. Лицензии и `THIRD-PARTY.md` обновлены; `clamscan.exe` в поставку не попал.
7. Документы обновлены, отчёт с PASS/FAIL/NOT RUN.
