# Скелет приложения OCHISTKA (этап 1) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать с нуля скелет OCHISTKA: окно Tauri 2 с левой навигацией на 10 разделов из CLAUDE.md; раздел «Главная» показывает загрузку CPU, использование RAM и список дисков через типизированную Tauri-команду на sysinfo (реальная реализация только для Windows).

**Architecture:** `ochistka-core` содержит DTO, чистые расчёты процентов и порт `SystemInfoPort` без кода ОС. `ochistka-platform` реализует порт: `windows/` — адаптер на sysinfo (только чтение), `macos/` и `linux/` — заглушки, возвращающие `CoreError::Unsupported`. Команда `get_system_overview` вызывает порт в `spawn_blocking`, чтобы не блокировать главный поток. Svelte-интерфейс обращается к системе только через типизированную обёртку `api.ts`.

**Tech Stack:** Tauri 2, Rust (stable, edition 2021), sysinfo, serde, thiserror; Svelte 5 (руны), TypeScript, Vite; Vitest + jsdom + @testing-library/svelte; Prettier + prettier-plugin-svelte; svelte-check; npm workspaces (`apps/desktop`).

**Spec:** `CLAUDE.md` в корне репозитория (копия загруженных инструкций).

**Вне этапа 1:** антивирус, любые действия очистки и удаления, переключатель ОС в «Драйверах» (раздел остаётся заглушкой «в разработке»), ИИ, аналитика, отправка диагностики, GitHub Actions.

## Global Constraints

- Стек: Tauri 2, Rust, Svelte 5 + TypeScript, Vite. Структура: `apps/desktop` (Tauri и интерфейс), `crates/ochistka-core` (без UI и без кода ОС), `crates/platform` (адаптеры по ОС).
- Системный код только в `crates/platform`, за трейтом. Реальная реализация — в `crates/platform/src/windows/`. `macos/` и `linux/` — заглушки, возвращающие `Unsupported`.
- Интерфейс не вызывает системные команды. Только типизированные Tauri-команды.
- Только чтение системных сведений через sysinfo. Ничего в системе не удаляем и не меняем. Внешние команды на этом этапе не запускаем.
- Аналитику, отправку диагностики и GitHub Actions не добавляем.
- Проверки: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `svelte-check --fail-on-warnings`, `vitest run`, Prettier `--check`.
- Тексты интерфейса на русском. Ровно 10 разделов с заголовками из CLAUDE.md, в этом порядке: Главная, Очистка, Программы, Процессы, Сеть, Безопасность, Виджеты, Оптимизация, Драйверы, Настройки.
- Недоступная на ОС функция показывается выключенной, с причиной из `Unsupported`.
- Статус функций по ОС ведётся в `docs/platform-status.md`. Слово «работает» пишем только для проверенного на этой ОС.
- Conventional Commits, маленькие коммиты. Имя модели в коммитах и файлах репозитория не указываем.

## Review Focus

1. Диск с нулевым объёмом (пустой съёмный диск, привод без диска) → процент 0, без NaN и паники. Тест: `disk_with_zero_total_reports_zero_percent` (Task 2).
2. Свободного места больше объёма (некорректные данные драйвера) → занято 0, процент не больше 100. Тест: `disk_available_above_total_saturates` (Task 2).
3. Диск без имени (на Windows у части томов пустая метка) → в интерфейсе показывается путь монтирования. Тесты: `disk_without_name_uses_mount_point_as_label` (Task 2), `home_renders_cpu_memory_and_disks` (Task 6).
4. ОС без адаптера (macOS, Linux) → «Главная» показывает причину из `Unsupported`, а не пустой экран. Тест: `home_shows_unsupported_reason` (Task 6).
5. Уход с «Главной» во время опроса → таймер очищается, поздний ответ не меняет состояние. Тесты: `home_stops_polling_after_unmount`, `home_ignores_response_after_unmount` (Task 6).

```rust
pub fn clamp_percent(value: f32) -> f32;                       // NaN -> 0.0; диапазон 0.0..=100.0
pub fn usage_percent(used_bytes: u64, total_bytes: u64) -> f32; // total == 0 -> 0.0

#[derive(Serialize, Clone, Debug, PartialEq)] #[serde(rename_all = "camelCase")]
pub struct CpuStatus { pub usage_percent: f32, pub logical_cores: u32 }
impl CpuStatus { pub fn new(usage_percent: f32, logical_cores: u32) -> Self }

pub struct MemoryStatus { pub total_bytes: u64, pub used_bytes: u64, pub usage_percent: f32 }
impl MemoryStatus { pub fn new(total_bytes: u64, used_bytes: u64) -> Self }   // used = min(used, total)

pub struct DiskStatus { pub display_name: String, pub mount_point: String,
                        pub total_bytes: u64, pub used_bytes: u64, pub usage_percent: f32 }
impl DiskStatus { pub fn new(name: &str, mount_point: &str, total_bytes: u64, available_bytes: u64) -> Self }
// display_name = name, либо mount_point, если name пустой; used = total.saturating_sub(available)

pub struct SystemOverview { pub cpu: CpuStatus, pub memory: MemoryStatus, pub disks: Vec<DiskStatus> }

#[derive(Debug, thiserror::Error)]
pub enum CoreError {
    #[error("{feature} недоступно на {os}")] Unsupported { feature: String, os: String },
    #[error("ошибка чтения системных данных: {0}")] Probe(String),
}

pub trait SystemInfoPort: Send + Sync {
    fn overview(&self) -> Result<SystemOverview, CoreError>;
}
```

Все структуры DTO (`CpuStatus`, `MemoryStatus`, `DiskStatus`, `SystemOverview`) получают `Serialize` и `#[serde(rename_all = "camelCase")]`. Derived-поля (`usage_percent`, `used_bytes`, `display_name`) считаются в конструкторах, не в интерфейсе.
