# Перф: ресайз окна (2026-11-18)

Причины лага (по коду): фон-плитка перерисовывалась вместе с областью при каждом изменении размера (слой менял размер, поверх `overflow:hidden` + `border-radius` на большой цветной области), отступы окна и скругление цветной области. Опросы (setInterval) есть только на страницах Процессы и Главная и от размера окна не зависят; обработчиков resize в коде нет.

Исправление: узор `pop-pattern.png` (плитка 320 px, непрозрачность 0.16) лежит на отдельном слое `.stage::before` фиксированного размера (`max(2560px,100vw)` x `max(1440px,100vh)`, `will-change: transform`); при ресайзе его только обрезают границы области. Корень приложения `contain: layout paint`, скругление только у корня, цветная область без собственного радиуса и отступов. Фильтров, backdrop-filter и крупных теней нет.

Измерение: Playwright (headless Chromium, программная растеризация), 120 вызовов `setViewportSize` по кругу между 6 размерами, трассировка и CDP Performance.getMetrics, значения на один ресайз, два прогона до / после:

|       | растеризация (RasterTask) мс | задачи (Task) мс | layout мс | p95 ожидания кадра мс |
| ----- | ---------------------------- | ---------------- | --------- | --------------------- |
| до    | 22.5 / 9.1                   | 11.2 / 3.3       | 1.6 / 0.5 | 69.7 / 35.3           |
| после | 6.9 / 7.7                    | 4.0 / 4.2        | 0.5 / 0.7 | 39.0 / 40.4           |

Вывод: в headless заметна лишь разница в растеризации первого прогона, остальное в пределах шума (кадр ограничен 30 Гц самим setViewportSize). Реальный выигрыш на WebView2 с GPU не проверен (нет Windows): статус `implemented`, не `verified`.
