## Не доказано
- **Нет подтверждения успешного обхода внешнего DPI** и восстановления доступа к реально затруднённому ресурсу. GitHub Windows runner и localhost не воспроизводят провайдерскую фильтрацию.

## Следующий этап: ограниченная внешняя проверка эффективности (6Б.5Г)
1. Подготовить **добровольный, явно запускаемый** диагностический сценарий для тестового Windows-окружения на сетевом пути, где внешний DPI действительно присутствует; не запускать автоматически ни у пользователей, ни в обычном CI.
2. Проверить базовое состояние выбранного тестового адреса **до** старта движка: исходный HTTP/TLS результат, время/коды ошибок, подтверждение реального ограничения. Не собирать персональный трафик и не публиковать секреты.
3. Запускать только подписанный закреплённый WinDivert и зафиксированный `winws2.exe`, в **узком фильтре тестового направления** и на короткое время; проверять хэши, минимальные права, логирование без чувствительных данных.
4. Сравнить результат **после** применения проверяемой стратегии с контролем (без неё), подтвердить ответы целевого сервиса и отсутствие побочного ухудшения. Всегда останавливать процесс и очищать временные артефакты даже при ошибках.
5. При отсутствии тестовой среды с DPI честно зафиксировать блокер вместо выдуманной «успешности». Профиль и пользовательский переключатель включать только после воспроизводимого подтверждения и тестов отката.

## 6Б.5Г.2А: самостоятельный Windows-пакет диагностики (Claude, 21.11.2026)
- `tools/desync-core/ochistka_dpi_check.py` — простой запуск для непрограммиста (двойной щелчок на `.exe`, без Python и командной строки): окно на русском, права администратора НЕ запрашиваются автоматически (пользователь сам запускает «от имени администратора»), согласие только словом «ДА» на два вопроса (узкий перехват одного соединения; VPN/прокси выключены). Адрес сайта берётся из системного DNS, публичные IPv4 фильтруются, подлинность проверяет сертификат TLS. Затем вызывается тот же `external_dpi_probe.main` со всеми прежними ограничениями (SHA-256 пяти файлов, подпись драйвера, узкий фильтр, тайм-ауты, остановка и очистка, предпроверки прокси и чужого `winws2`). Отчёт `OCHISTKA-DPI-report-*.txt` — только имя сайта, исходы и время.
- Усиление проверки: SHA-256 двух оригинальных Lua теперь тоже закреплены в `external_dpi_probe.py` и проверяются до и после копирования (раньше Lua не сверялись); режим `--self-check` — офлайн-проверка набора без сети и драйвера.
- `.github/workflows/build-desync-diagnostic-package.yml` — только ручной запуск: PyInstaller (`--onedir`), сборка пакета из закреплённого Release (архив сверяется с SHA-256 из `desync.rs`), офлайн `--self-check` самого `.exe` и проверка, что подмена файла блокирует запуск; перехват, драйвер и внешние соединения не используются. Артефакт: ZIP + SHA-256.
- Тесты: 41 офлайн-проверка Python (12 новых: отказ без «ДА», отказ без прав без попытки повышения, остановка при неверных хэшах до вопросов, только ожидаемые флаги, отбор приватных адресов DNS, безопасный отчёт).
- Не изменено: `site_discord_profile() == None`, переключатель недоступен, Defender не отключается. Реальная проверка на внешнем DPI по-прежнему НЕ выполнялась (нужна сеть с настоящей фильтрацией и согласие владельца на запуск).
