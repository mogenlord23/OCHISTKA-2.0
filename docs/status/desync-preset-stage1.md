## 6Б.5Г.2Д — умный выбор доступа по каждому сервису (21.11.2026)

- Выбор пути для каждого сервиса: прямое соединение → VPN → один цельный Desync-профиль; итог — одно общее решение. Состояние VPN берётся из реального `ConnectionStatus` (`VpnSignal::from_status`): работающий VPN запрещает перехват; непроверенное VPN-подключение блокирует всё; VPN в режиме системного прокси покрывает только сайты, остальные сервисы он не покрывает.

Direct/VPN/Block-планы движок не запускают; повторный запуск не создаёт второй экземпляр; ошибки запуска и нехватка прав не выдаются за успех. Дополнительный запрет в `start_locked` при активном VPN (`VpnRunning`).
- Обратная защита: `VpnService::set_conflict_guard` — VPN не подключается, пока работает перехват (одновременных механизмов нет).
- Реестр подтверждённых покрытий `CONFIRMED_EXTERNAL_PROFILES` по-прежнему пуст: пока нет реального повторяемого опыта на Windows, Desync выбран быть не может. `--dry-run` доказательством не является. Пользовательский переключатель остаётся выключенным.

## 6Б.5Г.3Б — надёжная остановка пробного запуска и разбор сбоя Windows CI (21.11.2026)
- Единый путь остановки `stop_process` для ручной остановки, таймера, общего `stop()` и `shutdown()`: `kill()` повторяется ограниченно (3 попытки × до 1 с), «Выключено», удаление файла номера процесса и освобождение права `NetCoordinator` — только после подтверждения `has_exited()`. Таймер после неудачи продолжает попытки (не более 5 неудач подряд, без бесконечных потоков); после лимита процесс остаётся учтённым, пробный и обычный запуск и VPN заблокированы до успешной остановки. `shutdown()` возвращает ошибку при неудаче (в приложении пишется в stderr; остаток убирает `recover_on_start` при следующем запуске). Обычная `readiness()`, `CONFIRMED_EXTERNAL_PROFILES` и основной переключатель не менялись.

## 6Б.5Г.3Г — исправления по реальной Windows-сборке (21.11.2026)
- Загрузка NetZapret: `Downloader::download` получает `url_prefix` загружаемого `PinnedEngine`; начальный адрес проверяется по префиксу именно этого выпуска (раньше — всегда по префиксу sing-box, поэтому NetZapret отклонялся). Каждый движок допускается только под своим закреплённым выпуском, чужие репозитории, поддельные домены, http, порты и логины отклоняются. Редиректы, лимиты размера, SHA-256 архива и файлов не менялись. Причины ошибок теперь разные: адрес отклонён / HTTP-код / таймаут / TLS / DNS / нет соединения / слишком большой файл; «проверьте интернет» только для обрыва соединения. Адреса и ключи в ошибки и журнал не попадают (`without_url`).
- «Обход блокировок»: удалены отдельная панель, галочка согласия, кнопка и пользовательские оценки. Один переключатель в существующей карточке (тот же стиль, что у DNS): нажатие вызывает `desync_trial_start` с `consent: true`, повторное — `desync_trial_stop`. Состояния «Выключено / Подготовка… / Включено · осталось M:SS / Ошибка»; при ошибке переключатель выключен. Рядом сказано, что это временный тестовый режим на 2 минуты. Автозапуска нет, состояние читается из Rust раз в секунду только на вкладке. Rust-проверки (администратор, `NetCoordinator`, запрет VPN+Desync, подтверждённая остановка, 120 с) и пустой `CONFIRMED_EXTERNAL_PROFILES` без изменений.
- Личная подписка VPN: поле подписки больше не заполняется сохранённой ссылкой при открытии. Сохранённые серверы и настройки не удаляются; в репозитории и установщике нет личных подписок, `state.json` и ключей (данные лежат в `%LOCALAPPDATA%\OCHISTKA\vpn`).

## Ошибка 206 при запуске объединённого пресета (21.11.2026)

## Служба WinDivert и замер скорости (21.11.2026)
Проверка владельца на Windows: обход включился, YouTube ≈ 2 мин, Discord ≈ 3 мин; после выключения служба драйвера WinDivert осталась RUNNING без `winws2`.
- **Служба драйвера.** Перед запуском движка читается состояние службы (`sc.exe query WinDivert`, абсолютный путь `C:\\Windows\\System32\\sc.exe`, фиксированный, без переменных окружения и PATH). Если до нас служба не работала, а после запуска работает — программа запомнила это в `desync-state.json` (папка данных обхода). После остановки `winws2` (кнопка, таймер 120 с, выход, откат по замеру) служба с отметкой останавливается (`sc.exe stop WinDivert`) и проверяется повторным запросом; отметка снимается. Служба, уже работавшая до нас (другое VPN-приложение), не трогается. При запуске программы остаток после принудительного выхода убирается тем же путём. Если остановить не удалось: обход НЕ выключен (состояние «Ошибка», право `NetCoordinator` не освобождается, запуск и VPN отказывают), в интерфейсе «Драйвер не остановлен, перезагрузите компьютер»; повторное нажатие повторяет остановку. Системные вызовы — `crates/platform/src/windows/driver_service.rs`, правила — в core через методы адаптера (core о Windows не знает). Права администратора отдельно не запрашиваются (обход и так требует их); без них остановка службы даст ту же ошибку.
- **Замер скорости.** До включения (VPN уже выключен) и после — YouTube, Discord, контрольный адрес: время до первого ответа и до полной загрузки, лимит 15 с на запрос и 45 с на замер, в фоне (интерфейс: «Проверяем…»). Нет базового замера ни по одному адресу — обход не включается. Медленнее в 1,5 раза или на 5 с и больше по любому адресу и показателю, либо адрес не открылся (при работавшем базовом замере) — обход выключается через общий путь остановки: «С обходом сайты грузятся медленнее — обход отключён». Иначе остаётся до конца 120 с: «Сайты отвечают быстрее или так же; это не доказывает работу у провайдера». Добавлен порог шума 250 мс для правила «в 1,5 раза» (иначе 20 → 40 мс считалось бы замедлением). `functional_confirmed` по-прежнему всегда `false`, пресет не менялся, `CONFIRMED_EXTERNAL_PROFILES` пуст. Адрес без успешного базового замера (например, заблокирован напрямую) не сравнивается.
- Тесты (фейки, без сети/WinDivert): Rust core 566, platform 105, vitest панели; проверка типов под Windows без ошибок. Не проверено на Windows: реальная остановка службы, реальные замеры, время YouTube/Discord.
- Владельцу: `git pull`, `npm run dev`, включить обход, сообщить время YouTube и Discord и что написала программа; после выключения проверить `sc.exe query WinDivert` и другое VPN-приложение.
