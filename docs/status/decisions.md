## 2026-11-19: Оформление, исправления по тесту на реальной Windows (look2)
- Мгновенный выбор: интерфейс рисует рамку и переключатель сразу, команда идёт в фоне через очередь (клики выполняются по порядку, интерфейс не ждёт). Ошибка: рамка снимается, показывается короткое сообщение бэкенда. Команда и раньше шла через `spawn_blocking`; задержку давали ожидание ответа и защита от повторных кликов. Диалоги подтверждения убраны (бэкенд по-прежнему требует `confirmed: true`, интерфейс шлёт его всегда).
- Курсоры не менялись из-за обновления через `rundll32 user32.dll,UpdatePerUserSystemParameters` (оно не перечитывает схему курсоров надёжно). Теперь `SystemParametersInfoW(SPI_SETCURSORS, 0, NULL, SPIF_UPDATEINIFILE | SPIF_SENDCHANGE)` через крейт `windows` в новом модуле `crates/platform/src/windows/win32_ffi.rs` (единственный unsafe в платформе кроме FFI ClamAV, у каждого вызова есть SAFETY). Файлы `.cur` проверены тестом (тип 2, горячие точки внутри кадра, DIB 32 бита, высота удвоена, маска AND, длины кадров). Пути в реестре абсолютные. Имя схемы пишется в значение по умолчанию ветки, `Scheme Source` = 1 (пользовательская схема). Возврат восстанавливает точные прежние значения и снова вызывает SPI_SETCURSORS.
- Анимация: «Занят» (Wait) и «Фоновая работа» (AppStarting) рисуются как `.ani` (RIFF ACON: LIST INFO, anih, rate, seq, LIST fram из 16 кадров-`.cur` 32/48/64): бегущая дуга второго цвета схемы по дорожке (Wait) и внутри бейджа стрелки (AppStarting), фигура и узор те же, что в схеме. 16 кадров и 3 размера на кадр — компромисс размера файла (~0,5 МБ) и плавности. Кадры всех ролей рисуются параллельно (`std::thread::scope`). В интерфейсе превью анимации: вращающееся кольцо на плитке при наведении.
- Обои: Windows хранит текущие обои в `TranscodedWallpaper` и перезаписывает его при смене, поэтому «прежний путь» не возвращал фон. Перед первой сменой текущий файл копируется в `%LOCALAPPDATA%\OCHISTKA\Backup\wallpaper-previous.<ext>` (без расширения — `.jpg`: Windows определяет формат по содержимому), в резерв пишется путь копии и прежние `WallpaperStyle`, `TileWallpaper`, `JPEGImportQuality`. Возврат выставляет их обратно, ставит копию; нет копии — обои Windows `%SystemRoot%\Web\Wallpaper\Windows\img0.jpg`; обоев не было — пустая строка. Если текущий фон уже наш из старой версии (резерва нет), «прежним» считаются обои Windows по умолчанию. Значение резерва переименовано в `PreviousWallpaperFile`, старый `PreviousWallpaper` игнорируется. Кнопка «Вернуть прежний фон» и повторный клик идут одним путём.
- Чёткость: Windows пережимает любые обои в JPEG с качеством 85. Перед сменой ставятся `JPEGImportQuality=100`, `WallpaperStyle=10` (Заполнить), `TileWallpaper=0` (прежние значения в резерве). Вшитые оригиналы (`resources/wallpapers`, 146 файлов) побайтно совпадают с набором Offline старого приложения; это самые большие доступные версии (3840×2160 и выше; Source — 4 PNG 1672×941, не используются). Смена обоев теперь через `SystemParametersInfoW(SPI_SETDESKWALLPAPER)` в `win32_ffi.rs`, крейт `wallpaper` убран (пустую строку он не принимал).

## 2026-11-19: VPN (задача vpn)
- Причина «ничего не происходит»: раздел был заглушкой, Rust-команд VPN не существовало. Теперь команды `vpn_*` зарегистрированы в `lib.rs`, разрешений в `capabilities` не нужно (свои команды приложения доступны окну), сеть выполняет Rust, а не webview (CSP не менялся).
- Ядро: sing-box 1.14.4, как в 0.5.5 (те же SHA-256). Режим по умолчанию и пока единственный: системный прокси. Прокси выставляет приложение (HKCU Internet Settings: ProxyEnable, ProxyServer, ProxyOverride; AutoConfigURL временно убирается) с копией в `HKCU\Software\OCHISTKA\Backup\VpnProxy`; откат не трогает значения, если адрес прокси уже сменил кто-то другой. TUN отложен: нужны права администратора и драйвер Wintun.
- HTTPS: `reqwest` (blocking) с `native-tls`, то есть системный SChannel, а не rustls: нет C-зависимостей (aws-lc/ring) на сборке под Windows, используется хранилище сертификатов Windows. Зависимость только под `cfg(windows)`; на Linux загрузка подписки честно возвращает «только Windows». Заменить на rustls можно одной строкой в `crates/platform/Cargo.toml`, если понадобится.
- User-Agent: `OCHISTKA`; при ответах 400/401/403/404/406/410/422 или нечитаемом теле один повтор с `v2rayN/7.0 OCHISTKA` (часть сервисов отдаёт список только знакомым клиентам, так делала 0.5.5). Личных данных и идентификатора устройства (x-hwid из 0.5.5) не отправляем.
- Процесс ядра: дочерний процесс без окна, PID пишется в `%LOCALAPPDATA%\OCHISTKA\vpn\core.pid`. Job object не использован (небезопасный код без возможности проверки на Windows); вместо него при выходе (`RunEvent::Exit`) ядро останавливается, а после аварии при следующем запуске убивается процесс по PID, только если его имя `sing-box(.exe)`, и возвращается прокси из копии реестра.
- unsafe: один вызов `InternetSetOptionW` (две глобальные опции WinINet, чтобы браузеры подхватили смену прокси) в `crates/platform/src/windows/win32_ffi.rs`; объявление `extern "system"` без новых крейтов.
- Хранение: `%LOCALAPPDATA%\OCHISTKA\vpn\state.json` (сервера с ключами, ссылка подписки, правила) обычным JSON, DPAPI из 0.5.5 не перенесён (нет безопасной обёртки). Конфиг ядра с ключами пишется в `session\config.json` и стирается при отключении.
- Не поддерживается (честно пропускается с причиной): Clash YAML, Xray JSON, транспорты xhttp/kcp/quic, SS с плагином, `encryption` VLESS.

Приложения (процессы) работают через `find_process` ядра; в режиме прокси действует только для программ, которые сами используют системный прокси.
- Постер: убраны чёрный фон и `overflow`; скругление задано самим картинкам, чёрные разделители нарисованы их рамками. Тёмная кайма по дуге углов пропала (проверено по увеличенным скриншотам). Низ портрета (чёрная одежда) остался: это содержимое картинки владельца.

## 2026-11-19: Оформление, круг 3 (блок B)
- Причина «Не удалось работать с реестром. Операция успешно завершена»: `SystemParametersInfoW` в крейте `windows` возвращает `Err` с кодом 0, если функция вернула FALSE, а последний код ошибки не выставлен. Теперь `crates/platform/src/os_status.rs` (чистые функции, тест с `io::Error::from_raw_os_error(0)`) считает код 0 успехом в `win32_ffi` (курсоры, обои) и в записи/удалении значений реестра (`winreg`). Настоящий успех для курсоров проверяется чтением `HKCU\Control Panel\Cursors` назад (`verify_cursor_registry`); при расхождении Windows не просим обновляться и схема не помечается поставленной.
- Права администратора для курсоров не нужны: пишем только в HKCU, `SPI_SETCURSORS` от прав не зависит.
- Тексты ошибок ядра: техническая часть (`{0}`) остаётся для журнала, пользователю показывается фраза без слов «реестр» и кодов.
- Прозрачность и заливка панели задач взаимоисключающие внутри одного запроса (ядро: включение одного возвращает прежнее значение другого), одна запись и одна рассылка. Очередь интерфейса пропускает команду, если более новый клик по тому же выбору ещё не дал ей начаться.
- Плитки курсоров: вертушка при наведении убрана.
- Обои: ровно 7 сплошных плиток (кислотные розовый, лайм, жёлтый, голубой; чёрный; белый; красный). Узор `pop-pattern.png` вшит в ядро через `include_bytes!` (путь `apps/desktop/src/assets`), плитка 320 px на экране 1920 px (растёт с шириной экрана), слой 0,07, как в `App.svelte` и `PATTERN`; плитка предварительно смешивается с цветом и повторяется по экрану. Старые id сплошных обоев (`solid-acid-01` и др.) убраны.
- Не проверено на Windows: реальные эффекты SPI_SETCURSORS и смены обоев, вид PNG на рабочем столе. Проверено: тесты ядра и интерфейса, `cargo check` под `x86_64-pc-windows-msvc`, скриншоты `docs/status/appearance-fix-3/`.
