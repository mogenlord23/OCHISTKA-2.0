## Оформление: системные обои, курсоры, цвета (shots-8)

- Плитка обоев ставит настоящие обои Windows (крейт `wallpaper`, только cfg(windows)). Прежние обои пишутся один раз в HKCU\Software\OCHISTKA\Backup\Appearance (PreviousWallpaper); выбранная плитка там же (AppliedWallpaper). Повторный клик по выбранной = возврат и снятие обводки; повторный возврат ничего не делает. Выбор читается из Windows, а не из localStorage.
- Оригиналы (набор Offline, около 105 МБ) в git не кладём. Приложение ищет `%LOCALAPPDATA%\OCHISTKA\Wallpapers\<id>.jpg|jpeg|png|bmp`. Если файла нет, интерфейс отдаёт превью (base64), ядро кладёт его в `Wallpapers\thumbs` и ставит обоями; уведомление только в stderr-журнале. Старого репозитория с набором в этой среде нет (`/home/user/ochistka-src/Assets` отсутствует), имена файлов оригиналов приняты как `<id галереи>.jpg`.
- Кнопка «Скачать оригиналы» видна, пока оригиналов нет; это заглушка: пишет причину в `Wallpapers\ORIGINALS.txt` и в журнал. План установщика: положить набор Offline в эту папку при установке (необязательный компонент), сервер раздачи выбрать позже.
- Сплошные плитки рисуются PNG 64x64 в `Wallpapers\solid`.
- Курсоры: `.cur` 32x32 (PNG внутри ICO, остриё стрелки как горячая точка, рисунок по центру) генерируются вручную без зависимостей и unsafe (`appearance_cursor.rs`); данные плитки (цвет, второй цвет, узор) приходят из таблицы интерфейса и проверяются ядром. Тот же контур рисует SVG плитки. Пишутся роли Arrow и IBeam, имя схемы и Scheme Source в HKCU\Control Panel\Cursors, резерв в HKCU\Software\OCHISTKA\Backup\Cursors, обновление через `%SystemRoot%\System32\rundll32.exe user32.dll,UpdatePerUserSystemParameters` (абсолютный путь). Остальные роли (Hand, Wait, ...) и анимация `.ani` пока planned: в таблице нет анимированных схем, анимацию в интерфейсе не имитируем.
- Цвета: клик ставит акцент (AppliedAccent), повторный клик возвращает прежний акцент из резерва; общий «Вернуть оформление Windows» остался.
- Клик по плитке и кнопки обоев выполняются без диалогов (клик и есть действие, всё обратимо); диалоги остались у переключателей прозрачности и тем. Сообщения «Готово», «применено», «не подключено» убраны, остались только ошибки Windows.
- Курсор приложения (CSS) удалён: курсор теперь системный.

## 2026-11-19: значки приложений и плитки «Компьютера»
- Значки программ ищет бэкенд по `id` (пачками `programIcons`), процессов и автозагрузки по пути (`pathIcons`, до 32 за запрос). Порядок: DisplayIcon (кавычки, `,индекс`, `%VAR%` через порт) → логотип пакета Store из AppxManifest → основной exe в папке установки (по имени программы, без setup/unins) → основной exe рядом с деинсталлятором → сам деинсталлятор (у Inno и NSIS он несёт значок программы). Индекс значка из DisplayIcon пока не учитывается: берётся значок файла по умолчанию (`windows-icons` индекс не принимает); планируется.
- Значок снимается в самом крупном размере (256, затем 96 и 48). Если значок маленький и «вклеен» в центр большого холста, поля обрезаются. Дальше уменьшение Lanczos3 с предумножением альфы (без тёмной каймы) до 64 px (плитка 32 px x2 для HiDPI) и PNG. Чистая обработка пикселей лежит в `crates/platform/src/icon_image.rs` и проверена тестами на Linux.
- Кэш: память (до 3000 значков) и диск `%LOCALAPPDATA%\OCHISTKA\icon-cache`, один файл на ключ (хэш пути без регистра, mtime, размера файла и стороны значка), не больше 6000 файлов, лишние удаляются при запуске. Неудачи хранятся только в памяти, чтобы после установки или обновления значок появился при следующем запуске.
- Интерфейс после загрузки списка запускает фоновые пачки по 8 (до 3 параллельно); строка, попавшая на экран позже, ждёт ту же пачку, а не делает свой запрос. Упавшая пачка не запоминается как «нет значка». Виртуальные списки из откатанного коммита 097e860 не возвращались: вид списков одобрен владельцем и не менялся. CSP уже разрешает `img-src data: blob:`.
- Плитки «Компьютера»: рисунок каждой плитки центрирован по сетке 88x88 (проверяется тестом `ComputerIcon.test.ts`); CPU получил 4 контакта на сторону без касания скруглённых углов; GPU перерисован плоскими формами в общем стиле (радиус 12, чёрный корпус, акцент в цвете плитки); «Система» сдвинута на 3,5 px вниз, RAM на 1 px вверх.

## 2026-11-19: Оформление, исправления по тесту на реальной Windows (look2)
- Мгновенный выбор: интерфейс рисует рамку и переключатель сразу, команда идёт в фоне через очередь (клики выполняются по порядку, интерфейс не ждёт). Ошибка: рамка снимается, показывается короткое сообщение бэкенда. Команда и раньше шла через `spawn_blocking`; задержку давали ожидание ответа и защита от повторных кликов. Диалоги подтверждения убраны (бэкенд по-прежнему требует `confirmed: true`, интерфейс шлёт его всегда).
- Курсоры не менялись из-за обновления через `rundll32 user32.dll,UpdatePerUserSystemParameters` (оно не перечитывает схему курсоров надёжно). Теперь `SystemParametersInfoW(SPI_SETCURSORS, 0, NULL, SPIF_UPDATEINIFILE | SPIF_SENDCHANGE)` через крейт `windows` в новом модуле `crates/platform/src/windows/win32_ffi.rs` (единственный unsafe в платформе кроме FFI ClamAV, у каждого вызова есть SAFETY). Файлы `.cur` проверены тестом (тип 2, горячие точки внутри кадра, DIB 32 бита, высота удвоена, маска AND, длины кадров). Пути в реестре абсолютные. Имя схемы пишется в значение по умолчанию ветки, `Scheme Source` = 1 (пользовательская схема). Возврат восстанавливает точные прежние значения и снова вызывает SPI_SETCURSORS.
- Анимация: «Занят» (Wait) и «Фоновая работа» (AppStarting) рисуются как `.ani` (RIFF ACON: LIST INFO, anih, rate, seq, LIST fram из 16 кадров-`.cur` 32/48/64): бегущая дуга второго цвета схемы по дорожке (Wait) и внутри бейджа стрелки (AppStarting), фигура и узор те же, что в схеме. 16 кадров и 3 размера на кадр — компромисс размера файла (~0,5 МБ) и плавности. Кадры всех ролей рисуются параллельно (`std::thread::scope`). В интерфейсе превью анимации: вращающееся кольцо на плитке при наведении.
- Обои: Windows хранит текущие обои в `TranscodedWallpaper` и перезаписывает его при смене, поэтому «прежний путь» не возвращал фон. Перед первой сменой текущий файл копируется в `%LOCALAPPDATA%\OCHISTKA\Backup\wallpaper-previous.<ext>` (без расширения — `.jpg`: Windows определяет формат по содержимому), в резерв пишется путь копии и прежние `WallpaperStyle`, `TileWallpaper`, `JPEGImportQuality`. Возврат выставляет их обратно, ставит копию; нет копии — обои Windows `%SystemRoot%\Web\Wallpaper\Windows\img0.jpg`; обоев не было — пустая строка. Если текущий фон уже наш из старой версии (резерва нет), «прежним» считаются обои Windows по умолчанию. Значение резерва переименовано в `PreviousWallpaperFile`, старый `PreviousWallpaper` игнорируется. Кнопка «Вернуть прежний фон» и повторный клик идут одним путём.
- Чёткость: Windows пережимает любые обои в JPEG с качеством 85. Перед сменой ставятся `JPEGImportQuality=100`, `WallpaperStyle=10` (Заполнить), `TileWallpaper=0` (прежние значения в резерве). Вшитые оригиналы (`resources/wallpapers`, 146 файлов) побайтно совпадают с набором Offline старого приложения; это самые большие доступные версии (3840×2160 и выше; Source — 4 PNG 1672×941, не используются). Смена обоев теперь через `SystemParametersInfoW(SPI_SETDESKWALLPAPER)` в `win32_ffi.rs`, крейт `wallpaper` убран (пустую строку он не принимал).
- Сплошные обои возвращены первой группой: 10 кислотных (каждая третья пара старой таблицы), чёрный, белый, серый, графит, тёмно-синий, бордовый, у некоторых едва заметный узор (точки, диагонали, сетка, 5,5% чёрного, как в старом приложении). Узор-картинка `pop-pattern.png` не берётся. PNG рисуется в Rust (`appearance_wallpaper.rs`, крейт `png`) в физическом разрешении основного экрана (`EnumDisplaySettingsW`), если неизвестно — 3840×2160. Таблица цветов — `crates/ochistka-core/assets/solid-wallpapers.json`, её читают Rust и интерфейс.
- Цвета: список без повторов и близнецов (расстояние RGB не меньше 20, проверяется тестом), порядок: кислотные (36), обычные, белый, серые, чёрный; всего 69. Выбор цвета меняет только `AccentColor`, `AccentPalette`, `ColorizationColor`, `AccentColorMenu` (`StartColorMenu` и `ColorPrevalence` больше не пишутся, тема не трогается). Убраны «тёмный/светлый режим» и «режим для Пуска» вместе с командами `setTheme`/`setSystemTheme`. Переключатели «Эффект прозрачности» и «Залить панель задач и Пуск» по умолчанию выключены: «включён» означает «включён нами», при включении прежнее значение запоминается (`Toggle.*`), повторный клик возвращает его. «Вернуть оформление Windows» сбрасывает всё сразу.
- Рассылка о смене цветов: один `SendMessageTimeoutW(HWND_BROADCAST, WM_SETTINGCHANGE, 0, "ImmersiveColorSet", SMTO_ABORTIFHUNG, 200 мс)` на запрос, проводник не перезапускается, повторных рассылок нет (тест: ровно одна на запрос цвета или переключателя, ни одной на остальные).
- Подпись «Оформление» на правой панели: шрифт системный Segoe UI (не вшит). Вес 800 на Windows может выбрать «Segoe UI Black», он шире. Теперь вес 700, 10,5 px, межбуквенный 0, отступы 4 px, `text-overflow: clip`; в худшем случае (Black) подпись занимает около 72% плитки.
- Не проверено на Windows: реальные эффекты SPI_SETCURSORS, SPI_SETDESKWALLPAPER, JPEGImportQuality, рассылка цветов, вид `.ani` в системе, ширина подписи в Segoe UI. Проверено: тесты ядра и таури на подставных реестре и файлах, структура `.cur` и `.ani`, `cargo check` под `x86_64-pc-windows-msvc`, скриншоты (`docs/status/appearance-fix-2/`).
