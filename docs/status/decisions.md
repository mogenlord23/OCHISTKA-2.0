## Оформление: системные обои, курсоры, цвета (shots-8)

- Плитка обоев ставит настоящие обои Windows (крейт `wallpaper`, только cfg(windows)). Прежние обои пишутся один раз в HKCU\Software\OCHISTKA\Backup\Appearance (PreviousWallpaper); выбранная плитка там же (AppliedWallpaper). Повторный клик по выбранной = возврат и снятие обводки; повторный возврат ничего не делает. Выбор читается из Windows, а не из localStorage.
- Оригиналы (набор Offline, около 105 МБ) в git не кладём. Приложение ищет `%LOCALAPPDATA%\OCHISTKA\Wallpapers\<id>.jpg|jpeg|png|bmp`. Если файла нет, интерфейс отдаёт превью (base64), ядро кладёт его в `Wallpapers\thumbs` и ставит обоями; уведомление только в stderr-журнале. Старого репозитория с набором в этой среде нет (`/home/user/ochistka-src/Assets` отсутствует), имена файлов оригиналов приняты как `<id галереи>.jpg`.
- Кнопка «Скачать оригиналы» видна, пока оригиналов нет; это заглушка: пишет причину в `Wallpapers\ORIGINALS.txt` и в журнал. План установщика: положить набор Offline в эту папку при установке (необязательный компонент), сервер раздачи выбрать позже.
- Сплошные плитки рисуются PNG 64x64 в `Wallpapers\solid`.
- Курсоры: `.cur` 32x32 (PNG внутри ICO, остриё стрелки как горячая точка, рисунок по центру) генерируются вручную без зависимостей и unsafe (`appearance_cursor.rs`); данные плитки (цвет, второй цвет, узор) приходят из таблицы интерфейса и проверяются ядром. Тот же контур рисует SVG плитки. Пишутся роли Arrow и IBeam, имя схемы и Scheme Source в HKCU\Control Panel\Cursors, резерв в HKCU\Software\OCHISTKA\Backup\Cursors, обновление через `%SystemRoot%\System32\rundll32.exe user32.dll,UpdatePerUserSystemParameters` (абсолютный путь). Остальные роли (Hand, Wait, ...) и анимация `.ani` пока planned: в таблице нет анимированных схем, анимацию в интерфейсе не имитируем.
- Цвета: клик ставит акцент (AppliedAccent), повторный клик возвращает прежний акцент из резерва; общий «Вернуть оформление Windows» остался.
- Клик по плитке и кнопки обоев выполняются без диалогов (клик и есть действие, всё обратимо); диалоги остались у переключателей прозрачности и тем. Сообщения «Готово», «применено», «не подключено» убраны, остались только ошибки Windows.
- Курсор приложения (CSS) удалён: курсор теперь системный.

## 2026-11-19: значки приложений и плитки «Компьютера»
- Значки программ ищет бэкенд по `id` (пачками `programIcons`), процессов и автозагрузки по пути (`pathIcons`, до 32 за запрос). Порядок: DisplayIcon (кавычки, `,индекс`, `%VAR%` через порт) → логотип пакета Store из AppxManifest → основной exe в папке установки (по имени программы, без setup/unins) → основной exe рядом с деинсталлятором → сам деинсталлятор (у Inno и NSIS он несёт значок программы). Индекс значка из DisplayIcon пока не учитывается: берётся значок файла по умолчанию (`windows-icons` индекс не принимает); планируется.
- Значок снимается в самом крупном размере (256, затем 96 и 48). Если значок маленький и «вклеен» в центр большого холста, поля обрезаются. Дальше уменьшение Lanczos3 с предумножением альфы (без тёмной каймы) до 64 px (плитка 32 px x2 для HiDPI) и PNG. Чистая обработка пикселей лежит в `crates/platform/src/icon_image.rs` и проверена тестами на Linux.
- Кэш: память (до 3000 значков) и диск `%LOCALAPPDATA%\OCHISTKA\icon-cache`, один файл на ключ (хэш пути без регистра, mtime, размера файла и стороны значка), не больше 6000 файлов, лишние удаляются при запуске. Неудачи хранятся только в памяти, чтобы после установки или обновления значок появился при следующем запуске.
- Интерфейс после загрузки списка запускает фоновые пачки по 8 (до 3 параллельно); строка, попавшая на экран позже, ждёт ту же пачку, а не делает свой запрос. Упавшая пачка не запоминается как «нет значка». Виртуальные списки из откатанного коммита 097e860 не возвращались: вид списков одобрен владельцем и не менялся. CSP уже разрешает `img-src data: blob:`.
- Плитки «Компьютера»: рисунок каждой плитки центрирован по сетке 88x88 (проверяется тестом `ComputerIcon.test.ts`); CPU получил 4 контакта на сторону без касания скруглённых углов; GPU перерисован плоскими формами в общем стиле (радиус 12, чёрный корпус, акцент в цвете плитки); «Система» сдвинута на 3,5 px вниз, RAM на 1 px вверх.

## 2026-11-19, UI fix (плавность окна, анимации, флажки, значок, GPU)

- Окно: `transparent: false`, `shadow: true`, `backgroundColor: #0b0b0b`. Прозрачное окно без рамки в WebView2 на Windows заметно тормозит при перетаскивании края; скругление углов и тень даёт сама Windows 11 (на Windows 10 углы квадратные). Скругление корня приложения в CSS убрано. Реализовано, на Windows не проверено: проверить плавность и вид углов.
- `watchMaximized` раньше на каждое событие размера делал обмен с ядром (`isMaximized`) десятки раз в секунду; теперь одно чтение через 120 мс после остановки.
- Слой узора: `contain: strict` + `will-change: transform`; у `main` `contain: layout paint`. Замер в headless Chromium (цикл из 120 изменений размера, CDP Performance): компоновка 0,3-0,7 мс и пересчёт стилей 0,3-0,5 мс на кадр на всех страницах до и после; шум замеров больше разницы, на Linux без GPU-композитора эффект не виден. Основной выигрыш ожидается от окна и IPC, на Windows не измерен.
- Анимации: смена страницы и вкладки 180-220 мс (opacity + translateY), блоки страницы появляются по очереди (шаг 28 мс), очередь только для первых 12 блоков, остальные без анимации. Нажатие кнопки scale(0.96). `prefers-reduced-motion` отключает всё.
- `Check.svelte` (checked, disabled, label, onchange; `bare` для случая внутри чужого label, `controlled` для состояния, которое подтверждает бэкенд): квадрат как в «Оформление → Цвета», размер 1.2em (18-22 px), настоящий input внутри. Подключён в TweakCard (Настройки, Boost), Диски, Вирусы. В Программах и Процессах флажков нет (выбор строк через aria-pressed).
- Значок: из pop-art.png старого приложения (материалы владельца) вырезан квадрат 1024, скруглённый, поля 5% (рисунок занимает 90% холста). icon.ico: 16, 20, 24, 32, 40, 48, 64, 96, 128, 256. В `bundle.icon` первым стоит icon.ico, значок окна задаётся при запуске (`set_icon`, feature `image-png`).
- GPU: sysinfo на Windows не отдаёт загрузку, поэтому читаем WMI `Win32_PerfFormattedData_GPUPerformanceCounters_GPUEngine`, сумма движков engtype_3D на адаптер, максимум 100 (чистая функция `aggregate_gpu_3d_load` в core с тестами). Одна карта получает наибольшую загрузку, при равном числе адаптеров и карт по порядку, иначе пусто (не гадаем). Если нет данных, интерфейс показывает «—» и причину. Реализовано, на Windows не проверено.
