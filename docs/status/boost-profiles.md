# Boost: состав профилей

Дата: 2026-11-19 (круг 5, этап T1). Код: `crates/ochistka-core/src/tweaks.rs` (`PROFILES`), тесты `profiles_have_exactly_the_documented_content` и соседние. Статус: **implemented, not verified на Windows**.

Профиль — набор отдельных параметров (те же, что в «Отдельных оптимизациях») и, при необходимости, схема электропитания. Профили взаимоисключающие; повторное нажатие на активный возвращает всё сохранённое.

| Профиль | Параметры | Схема питания | Права |
|---|---|---|---|
| Базовый | `game_dvr` (фоновая запись игр выключена: `GameDVR_Enabled`, `AppCaptureEnabled`, `HistoricalCaptureEnabled` = 0), `game_mode` (`AutoGameModeEnabled`, `AllowAutoGameMode` = 1) | не меняется (возвращается прежняя) | пользователь |
| Игровой | то же | «Высокая производительность» `8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c` (если скрыта, создаётся `powercfg /duplicatescheme guid guid`) | пользователь |
| Максимум | то же + `power_throttling` (`PowerThrottlingOff`=1, HKLM) | «Максимальная производительность» `e9a42b02-d5df-448d-aa00-03f14749eb61` (создаётся тем же способом) | `power_throttling` требует администратора |

VBS/HVCI, HAGS и политика Game DVR в профили не входят (отдельные переключатели; VBS/HVCI с подтверждением).

## Что было не так (круг 4)
- «Игровой ничего не меняет»: схема «Высокая производительность» на части компьютеров (современный режим ожидания) скрыта; `powercfg /setactive` отказывал, а адаптер создавал скрытую схему только для Ultimate. Теперь создаёт и для «Высокой». Когда параметры и схема уже были как в профиле, изменений и правда не видно: теперь под переключателем показан список «что включено» с состоянием каждого пункта.
- «Максимум даёт ошибку»: недоступная схема Ultimate (редакции без неё, ограничения политики) обрывала весь профиль. Теперь пункт пропускается с причиной «Эта схема электропитания недоступна на этом компьютере.», остальное применяется, профиль считается включённым.
- «Базовый включает два параметра»: это и есть описанный состав (`game_dvr` + `game_mode`), список теперь виден в интерфейсе.

## Поведение
- Применение: схема питания первой (если powercfg откажет, реестр не тронут), затем обязательные параметры (ошибка здесь прерывает и откатывает параметр), затем необязательные: недоступные (нет прав администратора, версия Windows) пропускаются с причиной, записанной в `HKCU\Software\OCHISTKA\Backup\boost` значением `skip_<id>`.
- Активный профиль определяется по реальному состоянию: маркер профиля, все обязательные параметры применены, схема питания применена либо пропущена с причиной. Если пользователь сменил схему или параметр вручную, профиль не показывается активным.
- Откат: прежняя схема питания и прежние значения реестра (`Backup`), как раньше.
