# Конфигурация ядра для «Только сайты»

Это то, что приложение передаёт ядру (sing-box) в области «Только сайты». Образец построен на вымышленном сервере, адрес сервера и ключи заменены метками `<адрес сервера>` и `<ключ>`. Список сайтов в образце: встроенный список (`assets/sites/builtin.txt`) и один сайт пользователя `user-site.example`; у владельца к встроенному списку добавляются сайты из панели «Мои сайты», без повторов. Создан командой `cargo run -p ochistka-core --example dump_vpn_config -- <папка>`; формат проверяет `sing-box check` на CI (workflow `vpn-config-check`).

Как читать:
1. `hijack-dns` — запросы имён из туннеля обрабатывает ядро.
2. Адрес сервера — напрямую (иначе соединение с сервером попало бы в туннель).
3. Локальные адреса (`ip_is_private`) — напрямую.
4. Домены из списка и все их поддомены (`domain_suffix`) — через VPN (`proxy`).
5. Всё остальное — напрямую (`route.final = direct`).
6. Имена сайтов из списка разрешаются через VPN (`remote`), остальные — локально (`dns.final = local`).
7. Системный прокси Windows не используется; весь трафик перехватывает туннельный адаптер.
