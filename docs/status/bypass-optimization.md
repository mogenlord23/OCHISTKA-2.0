# Скорость включения «Обхода блокировок»

Цель: путь от нажатия до готового обхода без лишних ожиданий. Интерфейс реагирует сразу (оптимистичный переключатель), движок честно стартует в фоне.

## Где уходило время (по коду и сообщению владельца: ~10 с до «Включено»)
| Этап | Было | Стало |
|---|---|---|
| Остановка VPN | только если VPN работает | без изменений |
| Замер без обхода | последовательно ДО подготовки, до 8 с (закрытый сайт ждал предел запроса 5 с) | параллельно с подготовкой, лимит 3 с, свежий результат (≤ 5 мин) берётся без нового замера |
| Проверка SHA-256 встроенных файлов (≈ 270 файлов, ~4,5 МБ + движок) | дважды за нажатие (`locate` и `spawn`), чтение и хэш каждого файла | один раз при старте программы в фоне; дальше проверка по размеру и времени изменения файла, изменение файла сбрасывает запись |
| Запуск процесса и проверка, что он не упал | фиксированные 5 × 200 мс = 1 с ожидания | 8 × 50 мс = 400 мс (ранний выход сразу при падении) |
| Служба WinDivert | запрос состояния до и после запуска | без изменений |

## Цифры на фейках (без диска, сети и Windows; логика и порядок, не реальная скорость)
`StartTimings` одного запуска: остановка VPN 1 мкс, подготовка 42 мкс, ожидание замера 192 мкс, процесс 2,3 мс (на фейке ожидание = 2 × 1 мс), всего 2,6 мс. Тест на параллельность: подготовка 400 мс + замер 400 мс дают запуск < 760 мс (последовательно было бы ≥ 800 мс). Тест кеша: вторая проверка 0 новых хэшей из 262+ файлов; подмена файла (другой размер или то же при новом времени изменения) обнаруживается.
Реальные цифры на Windows: каждый запуск пишет одну строку в `desync-start.log` (папка данных обхода): «запуск: всего N мс (VPN …, подготовка …, ожидание проверки …, процесс …)». Не измерено: время чтения файлов под Защитником Windows, время самого `winws2` и службы WinDivert.
