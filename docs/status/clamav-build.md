# Сборка libclamav из исходников — статус (2026-11-18)

- Попытка: скачать исходники ClamAV с GitHub (`Cisco-Talos/clamav`, архив `main`) из среды разработки.
- Результат: **не собрано**. Запрос к GitHub вернул HTTP 403 через прокси среды; сайт clamav.net тоже 403. Исходники недоступны, поэтому CMake-сборка и MSVC-сборка не выполнялись.
- Что сделано вместо этого: порт `VirusScanPort` и FFI-граница описаны в коде; движок на этом этапе — заглушка, которая честно отвечает «движок ClamAV не собран». Приложение не падает, раздел «Вирусы» показывает причину.
- Что нужно для продолжения: доступ к GitHub из среды сборки (или локальная копия исходников в `tools/clamav-build/`), затем Windows-сборка по `tools/clamav-build/README.md`.
- Статус по ОС: Windows — `planned` (сборка не выполнена); остальные ОС — не поддерживаются.

## Обновление: источник найден (2026-11-18)

- Исходники ClamAV 1.4.6 доступны через зеркало Debian (`deb.debian.org`), не через GitHub. Скачивание и проверка SHA-256 — `tools/clamav-build/fetch.sh`.
- Конфигурация CMake на Linux остановилась на обязательных зависимостях `libxml2` и `pcre2`. Установка системных пакетов в этой среде заблокирована политикой; сборка не выполнена.
- Чтобы закрыть пункт: установить `libxml2-dev` и `libpcre2-dev` (Linux) или подготовить vcpkg (Windows), затем по `tools/clamav-build/README.md`.

## Итог сборки на Linux (2026-11-18)

- libclamav 1.4.6 собран статически (`clamav_static`, `libclamav_static.a`) на Linux. Для этого по разрешению владельца установлены системные пакеты: libxml2, pcre2, json-c, libcurl, libmspack.
- Из исходников Debian удалены компоненты unrar и mspack (лицензии); конфигурация: `ENABLE_UNRAR=OFF`, `ENABLE_EXTERNAL_MSPACK=ON`.
- Экспорт: `cl_init`, `cl_engine_new`, `cl_load`, `cl_engine_compile`, `cl_scanfile`, `cl_engine_free`, `cl_retver`, `cl_strerror` найдены в библиотеке. Сигнатуры в `crates/platform/src/windows/clamav_ffi.rs` совпадают с `libclamav/clamav.h` (сверено по исходникам).
- Не проверено: сборка под Windows (MSVC), линковка Rust-модуля с библиотекой, загрузка сигнатур (нужны базы: freshclam), сканирование EICAR с реальной базой.
- Фича `libclamav` в `crates/platform` остаётся выключенной по умолчанию.

## Проверка библиотеки на Linux (2026-11-18)

- Небольшая программа на C, связанная с `libclamav_static.a` и `libclamav_rust.a`, выполняет: `cl_init` (0), `cl_retver` (1.4.6), `cl_engine_new`, `cl_load` из пустой папки (код 8 — баз нет, ожидаемо), `cl_engine_compile` (0), `cl_scanfile` (0, без сигнатур).

## 2026-11-23: Linux, проверка FFI и тестовой сигнатуры

- Исходники Debian ClamAV 1.4.6 получены существующим `fetch.sh`, SHA-256 совпал с закреплённым значением. Архив содержит лицензии GPL-2.0 и сторонних компонентов, которые необходимо учитывать при поставке.
- В изолированном каталоге `/workspace/.ochistka-tooling` собран `clamav_static` на Linux x86_64 с внешней libmspack и отключённым UnRAR. Компоненты сборки получены из подписанного индекса Debian. Это локальная сборка, не артефакт приложения.
- Заголовок `clamav.h` показал, что прежняя структура `cl_scan_options` пропускала поле `general`, а `CL_DB_STDOPT` был неверен. Исправлены структура и опции, загрузка нулевого числа сигнатур отклоняется.
- Rust-обёртка с явно включённой фичей связана с собранной библиотекой на Linux. Тестовая HDB-сигнатура обнаружила безопасный EICAR, чистый файл не сработал, повреждённая тестовая база отклонена. Это не проверка официальных баз, их обновления или защиты компьютера.
- Фича `libclamav` по умолчанию остаётся выключенной. Запуска приложения, теста на Windows/macOS и обновления официальных баз в этой проверке не было.

## Ход работы: прогресс и ограничения

- Ядро сообщает фактическое число обработанных, проверенных, пропущенных и недоступных файлов после обхода дерева. Пока идёт поиск файлов, экран показывает подготовку списка без выдуманного процента. Новый канал прогресса Tauri дополняет прежнюю команду, а поздние события завершённой проверки игнорируются.
- Неполный обход отмечается также при ограничении глубины и недоступных вложенных папках. При ошибках и пропусках экран находок не называет проверку полной. Проверка доступа на Linux проведена на временной папке с запрещённым чтением.
- Linux: `cargo check` приложения прошёл с GTK/WebKit, распакованными локально из пакетов Debian. Это компиляция, не проверка GUI и не включение ClamAV по умолчанию. Выборочные интеграционные тесты используют временные файлы и подставной движок, кроме отдельно указанной проверки FFI с тестовой HDB-базой.
- Полная проверка `ochistka-platform` в этом контейнере завершилась ошибкой сетевого теста `finds_own_listening_socket_with_pid` (102 теста прошли, один упал). Полный Clippy с `-D warnings` завершился на ранее существовавших замечаниях в тестах служб и VPN. `clippy --lib` для ядра и платформы прошёл.
- Доступ к `https://database.clamav.net/daily.cvd` из этой среды вернул HTTP 403. Официальные базы и их обновление не проверены. Доступ к пользовательской сети Windows и к macOS здесь отсутствует.
- Проверка одновременно не подтверждает защиту от подмены между сканированием и карантином. Текущий результат находки не содержит проверенного при сканировании хэша, а операции карантина требуют отдельного усиления для безопасной работы на всех трёх ОС. Не считать текущий карантин проверенным по этому требованию.

- Находка по-прежнему содержит только путь и сигнатуру; движок проверяет путь, а не открытый файловый дескриптор. Временно отклонён запрос переноса находок в карантин с сообщением о недоступности: этот путь раньше мог переместить подменённый файл или перезаписать назначение. Просмотр и восстановление существующих записей не отключены; существующее восстановление также не защищено от гонки перезаписи и требует доработки.

SHA-256, устройство, inode и размер получаются из открытого файла; изменение метаданных во время чтения приводит к отказу. Это самостоятельная подготовительная операция, не связанная с результатом сканирования и не выполняющая перенос. Идентификатор может быть повторно использован файловой системой; метаданные и хэш не дают абсолютной защиты от конкурентной записи.

Полноценный безопасный адаптер перемещения/восстановления — planned; атомарная установка и межтомный перенос не реализованы, перенос находки пока всегда отклоняется. Обычный `renameat2` с `RENAME_NOREPLACE` сам по себе не связывает имя источника с ранее открытым дескриптором: безопасность от подмены требуется доказать отдельно. При недоступном procfs открытие завершается ошибкой.
