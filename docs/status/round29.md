# Круг 29: движок проверки — официальная сборка ClamAV и базы

## Решение владельца

«Ждём движок, чтобы всё работало». Режим «по признакам» без базы не делается.

**Поправка к ADR 0004:** движок берётся из официальной подписанной сборки ClamAV из GitHub Releases,
а не собирается из исходников. Причина: на машине нет `vcpkg`, на `C:` было 0,4 ГБ свободно, сборка
из исходников — часы и высокий риск. Версия и SHA-256 закреплены в `tools/clamav-win/fetch.ps1`.
В приложение входят только `libclamav.dll` и её DLL-зависимости; `clamscan.exe`, `freshclam.exe`,
`clamd.exe` и прочие программы из архива не поставляются и не запускаются.

## Что сделано

- **T1. Закрепление сборки** (`fcd7578`). `tools/clamav-win/fetch.ps1` скачивает
  `clamav-1.4.6.win.x64.zip` по закреплённому адресу, проверяет размер (191 947 200 байт) и SHA-256
  `57b6fd1d…95fd` (совпадает с полем `digest` в GitHub API), распаковывает только заголовки,
  `clamav.lib` и DLL; программы не распаковываются. Повторный запуск берёт проверенный архив и не
  ходит в сеть. Если версия или хэш не совпали — остановка с понятной ошибкой, без тихой замены на
  1.5.5.
- **T2. Сборка с движком** (`3d54bb0`). `crates/platform/build.rs` при включённой фиче `libclamav`
  и наличии `tools/clamav-win` добавляет путь к `clamav.lib` и копирует DLL в каталог профиля и в
  `deps` (там живут тестовые бинарники). Без папки сборка не меняется. Фича `libclamav`
  проброшена из `apps/desktop/src-tauri/Cargo.toml`.
- **T3. Базы и статус** (`c7681f0`). Папка баз `%LOCALAPPDATA%\OCHISTKA\clamdb` создаётся при
  старте; если в ней есть файлы, движок загружает их в фоне. Новые команды `clamav_signatures` и
  `clamav_load_signatures`; движок сообщает число сигнатур. Экран «Проверка» при незагруженной
  базе пишет «Базы проверки не загружены», показывает путь и кнопку «Открыть папку баз»; после
  загрузки — «База загружена: сигнатур — N».
- **T4. Тесты движка** (`6c6d1b4`). Юнит-тесты рядом с кодом: тестовая база `.ndb`, находка по
  своему образцу, чистый файл остаётся чистым, битая база даёт понятную причину и не ломает уже
  загруженную. Сквозные тесты `tests/virus_scan.rs` больше не пишут EICAR на диск (Defender его
  удаляет), а используют собственный безвредный образец и сгенерированную базу.
- **T5. Лицензии** (`c82e407`). `THIRD-PARTY.md`: релиз, размер, SHA-256, что поставляется и что
  нет. Текст GPL-2.0 из архива лежит в `apps/desktop/src-tauri/resources/licenses/ClamAV-GPL-2.0.txt`
  и включён в ресурсы установщика.
- **T6. Документация** — этот файл, поправка в `docs/adr/0004-own-engine.md`, checkpoint в
  `docs/status/clamav-build.md`, строка в `docs/platform-status.md`.

## Дополнение 2026-11-23 (по замечанию владельца): движок в обычном запуске

Владелец увидел в программе «Проверка пока недоступна», потому что обычная сборка шла без фичи
`libclamav`. Поправка: фича включена по умолчанию в `apps/desktop/src-tauri/Cargo.toml`, а
`build.rs` выставляет `clamav_linked` только когда сборка ClamAV действительно скачана. Поэтому
обычный запуск (`npm run dev` из корня) содержит движок; если папки `tools/clamav-win` нет, сборка
не падает и честно показывает «движок не собран» вместо ошибки линковки. Экран проверки при этом
пишет «Базы проверки не загружены», а не «Проверка недоступна».

Экран «Проверка» переделан по просьбе владельца: слева одна большая кнопка со щитом — нажатие на
неё и запускает проверку (отдельной кнопки «Начать проверку» больше нет), под ней папка, прогресс,
корзина и «Убрать выбранные»; справа — находки.

## Как владельцу положить базы

1. Скачать официальные базы ClamAV (`main.cvd`, `daily.cvd` и, по желанию, `bytecode.cvd`) на
   любом компьютере, где работает `https://database.clamav.net` (например, через обычный браузер
   на другом устройстве).
2. Открыть в OCHISTKA раздел «Вирусы» → «Проверка» и нажать «Открыть папку баз» — откроется
   `C:\Users\<Имя>\AppData\Local\OCHISTKA\clamdb`.
3. Положить туда скачанные файлы и перезапустить программу: база загрузится сама, на экране
   появится число сигнатур.

Сейчас с этой сети базы не скачать (сервер отвечает 403), поэтому шаг 1 нужно сделать там, где
доступ есть; приложение обходит это ограничение только честно — без сторонних зеркал.

## Ограничения и что осталось

1. **Официальные базы не скачаны** — их нет в сети с этой машины. Экран честно пишет «Базы
   проверки не загружены», проверка недоступна.
2. **Установщик**: DLL движка копируются рядом с `.exe` в dev- и обычной сборке, но упаковка в
   NSIS и раскладка ресурсов для установленного приложения в этом круге не проверялись.
3. **Обновление баз** (freshclam-подобный механизм) — отдельный этап; сейчас владелец кладёт файлы
   сам.
4. **Перенос находок в карантин** по-прежнему выключен (`FINDINGS_TRANSFER_READY = false`).

## Попутно: нехватка места и файла подкачки на C:

Во время сборки Windows показала предупреждение о нехватке места, а затем «Ошибка при запуске
приложения (0xc000012d)» — это исчерпание памяти подкачки, а не ошибка OCHISTKA.

- Освобождено место на `C:`: временные файлы, кэши браузера, кэш загрузок NVIDIA (≈3 ГБ).
- Крупные папки приложений перенесены на `B:` и связаны ссылками (junction), приложения работают
  как раньше: `CapCut` (12,6 ГБ), `FortniteGame` (5,6 ГБ). Итог: свободно было 0,06 ГБ, стало ≈17 ГБ.
- Добавлен файл подкачки на `B:` (16–32 ГБ), чтобы исчерпание памяти не повторялось; он
  включается после перезагрузки.

## Следующий шаг одной строкой
