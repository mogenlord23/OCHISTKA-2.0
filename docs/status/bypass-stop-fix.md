# Остаток winws2 после выключения обхода и закрытия программы

**Происшествие (Windows, f219488):** после выключения «Обхода блокировок» и закрытия программы `winws2` (PID 5244) остался работать и перехватывал трафик; служба WinDivert не установлена, прокси выключен; процесс завершён владельцем вручную.

## Что нашёл в коде (журнала Windows у меня нет: причина установлена по коду, точный сценарий владельца не воспроизведён)
1. **`winws2` — отдельный процесс, его ничто не привязывало к программе.** Завершение шло только через `RunEvent::Exit` и кнопку. Если программа закрыта без этого события (принудительное закрытие, остановка `npm run dev`, падение), никто не завершает движок, а очистка была только при СЛЕДУЮЩЕМ запуске. Пока программа не запущена снова, трафик перехвачен.
2. **Проверка «завершился» могла лгать.** `StdCoreProcess::has_exited` возвращал «завершился» и при ошибке опроса дескриптора (`!matches!(try_wait, Ok(None))`), а `stop_process` доверял этому и удалял файл с PID, не сверяясь с системой. Ошибка `TerminateProcess` (`let _ = child.kill()`) тоже терялась.
3. **Очистка по PID была неполной.** `kill_stale` завершал процесс только если читался путь к exe (при отказе доступа путь неизвестен — процесс не трогался), результат нигде не проверялся, а файл с PID удалялся в любом случае.

## Что изменено
- `crates/platform/src/windows/process_guard.rs`: поиск процесса по PID с проверкой ИМЕНИ (`winws2.exe`) и, если известен, пути из нашей папки; чужой процесс с тем же PID не трогается; завершение с проверкой, что процесса с таким PID и именем больше нет; `GuardedProcess`: «завершился» только если не завершился ни дескриптор, ни процесс по PID и имени, завершение без бесконечного ожидания (3 попытки: дескриптор, затем по PID). Если систему опросить не удалось, процесс считается живым (безопасный отказ).
- Задание Windows (`win32_ffi.rs`, единственное место с `unsafe`): `winws2` привязывается к заданию «завершить при закрытии», созданному один раз на программу. Принудительное закрытие или падение программы закрывает дескриптор задания, и система сама завершает движок. Ошибка привязки запуск не блокирует (остаются остановка по PID и очистка при старте).
- PID сохраняется в `desync.pid` сразу после запуска (так и было) и теперь не удаляется, пока завершение не подтверждено.
- Остановка (кнопка, таймер 120 с, откат по скорости, выход) всегда заканчивается проверкой по PID и имени. Не завершился — состояние «Ошибка», текст «Обход не выключился, перезагрузите компьютер», переключатель не показывает «Выключено», право запуска не освобождается (ни новый запуск, ни VPN), повторное нажатие повторяет остановку.
- При старте программы первым действием: PID из файла, процесс с таким PID и именем жив — завершается; не удалось — «Ошибка» с тем же текстом.
- Не менялись: пресет, панель «Сайты», откат по замеру, взаимоисключение с VPN, 135 файлов, `Universal V13 Lite.txt`.

## Проверка (Linux, без запуска `winws2`)
Тесты на фейках: выход при включённом обходе завершает движок и проверяет его по PID; принудительный выход → следующий запуск завершает старый движок по сохранённому PID; сбой завершения → «Ошибка», текст, переключатель не «Выключено», повтор доводит до конца; выживший старый движок при старте блокирует всё до завершения. Реальные процессы (`sleep` вместо `winws2`): чужой процесс с другим именем и тем же PID не трогается; одноимённый из другой папки не наш; завершение и проверка «его нет»; `GuardedProcess` завершает и сообщает «завершился» только когда процесса нет. Тип-проверка кода задания под `x86_64-pc-windows-msvc` проходит.

## Не проверено на Windows
Реальное поведение задания Windows (`KILL_ON_JOB_CLOSE`) для Cygwin-процесса `winws2` (в т. ч. вложенные задания и родительское задание `npm run dev`), реальное завершение `TerminateProcess`, видимость PID и имени процесса под Защитником, закрытие через `tauri dev`. Остаточный риск: если задание не удалось создать, а программа закрыта принудительно, движок живёт до следующего запуска программы (очистка по PID при старте).
