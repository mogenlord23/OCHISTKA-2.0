# Этап 6Б.5Г.1 — подготовка проверки внешнего DPI (21.11.2026)

- Добавлен `tools/desync-core/external_dpi_probe.py`: **только добровольный диагностический запуск** на Windows x64, **не** режим приложения. По умолчанию только план (вообще без сетевых соединений и запуска движка).
- Для реального опыта требуются 2 отдельных флага подтверждения, уже отключённый VPN, запущенная с правами администратора Windows-сессия, локально распакованный проверенный Release и заранее выбранные DNS-имя и публичный IPv4 **одного** тестируемого ресурса. Никакого автоповышения прав, подмены DNS/hosts, прокси или постоянной службы.
- Проверяются SHA-256 пяти компонентов `PINNED_WINDOWS` и статус `Valid` подписи `WinDivert64.sys`. Используются оригинальные Lua из репозитория. Не скачиваются чужие исполняемые файлы, не обходится Defender.
- Порядок: один прямой HTTPS GET `/` к указанному IP с SNI/проверкой сертификата выбранного имени → если доступ уже есть, стоп без движка → та же проверка при **строго ограниченном** WinDivert-фильтре (`ip.DstAddr`, `tcp.DstPort=443`, предварительно зарезервированный `tcp.SrcPort` нашего сокета) → остановка движка даже при ошибке → повторный контроль без двигателя. Никаких переходов по ссылкам и отправки cookie/ключей.
- Сам эксперимент ограничен тайм-аутами. Журнал движка хранится только во временном каталоге, не публикуется и удаляется; в отчёте лишь категория исхода, HTTP-код и длительность, без ответа сервера или содержимого пакетов.
- В `validate-desync-pin.yml` добавлены только **офлайн**-тесты безопасности и синхронизации хэшей с Rust. Никакой внешней проверки в обычном CI.
- Статус: **инструмент подготовлен, но реальная проверка DPI не выполнялась**. Наличие `200/302` только при включённом кандидате при двух одинаково неуспешных контролях — сигнал для повторного опыта на заведомо фильтруемой сети, а **не** доказательство причинности DPI или готовности профиля.
- `site_discord_profile()` = `None`, пользовательский «Обход блокировок» не включается. Сравнение Telegram/Discord UDP/QUIC, VPN и игр вообще не проводилось.

## Использование исключительно оператором испытания (после выбора среды с DPI)

Безопасное планирование (можно выполнять на любой ОС; хост и IP должны соответствовать реальному тестовому ресурсу):

```sh
python tools/desync-core/external_dpi_probe.py --host TEST_DOMAIN --ip PUBLIC_IPV4
```

Реальный запуск **только** на Windows в отдельной тестовой среде после явного согласия, с уже отключённым VPN, проверенным распакованным Release и запуском терминала от администратора:

```powershell
python tools/desync-core/external_dpi_probe.py --host TEST_DOMAIN --ip PUBLIC_IPV4 --bundle-dir PATH_TO_PINNED_RELEASE --execute --acknowledge-narrow-interception --confirm-vpn-off
```

При отсутствии среды с настоящим DPI ничего не запускать. Перед включением профиля в приложении требуется воспроизводимый результат на контролируемом внешнем маршруте, анализ побочных эффектов и тесты отката. Это не инструкция обычному пользователю OCHISTKA.
