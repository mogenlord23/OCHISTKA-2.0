## Подтверждено на настоящем Windows (журнал второго запуска)

- Установщик собирается и ставится тихо (`/S`) от администратора раннера в `C:\Program Files\OCHISTKA` (установка «для всех пользователей»).
- Журнал `%ProgramData%\OCHISTKA\install.log` создан; в нём: пользователь и права администратора, наличие файлов (`ochistka-vpn-host.exe` 345 088 байт, `sing-box.exe` 82 074 624 байт), создание службы, `sc sdset`, `sc qc`, итог.
- Служба `OchistkaVpn`: `LocalSystem`, тип запуска `DEMAND_START` (вручную), путь `C:\Program Files\OCHISTKA\vpn-service\ochistka-vpn-host.exe`; после установки `STOPPED`.
- Права службы содержат запись для Authenticated Users `(A;;LCRPWPLO;;;AU)` (состояние, запуск, остановка).
- Недопустимая конфигурация (`experimental.clash_api`) служба не принимает: сразу `STOPPED`.
- Допустимая проверочная конфигурация (локальный вход на 127.0.0.1, выход `direct`, без туннеля): через 5 секунд `RUNNING`, локальный вход ядра отвечает, процесс `sing-box` запущен, файл конфигурации с ключами стёрт после запуска.
- Остановка: `STOPPED` достигнуто, процесса `sing-box` нет.
- Удаление программы: служба удалена (`NOT_INSTALLED`).

## Замечание по журналу

Строки, которые пишет сам установщик (NSIS), в `install.log` выходили вопросительными знаками (запись идёт в ANSI). Исправлено: эти строки теперь латиницей; строки скрипта службы (кириллица) читаются нормально.

## Не проверено

- Реальный туннель TUN с подпиской владельца (в CI проверялась служба и ядро без туннеля: создание адаптера на раннере не запускалось).
- Запрос прав при установке на обычном компьютере владельца (в CI установка идёт уже от администратора) и причина прошлой неудачи установки службы обхода.
- Запуск и остановка службы обычным пользователем без прав администратора (CI проверяет только запись в правах).
- Достаточна ли длина аргумента запуска для большой конфигурации (в проверке она короткая).
- Defender и другие защиты на компьютере владельца.
