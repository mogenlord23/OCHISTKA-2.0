# ADR 0026: исключения VPN работают: прямой DNS и применение сразу

- **Дата:** 2026-11-22
- **Статус:** принято (по прямой просьбе владельца; уточняет ADR 0025 — исключения возвращаются как выбор пользователя, не как правило по умолчанию)

## Контекст

Владелец ставит «Российские сайты напрямую» (VPN → Дополнительно → Исключения), нажимает «Сохранить», но ya.ru не открывается. Причины по коду:

1. `set_rules` сохранял правила, но работающее ядро не перезапускал: конфигурация оставалась прежней.
2. Прямые домены разрешались сервером имён `local` (системный резолвер). В туннеле у Windows в списке DNS стоит сам адаптер туннеля, поэтому запрос возвращался ядру и не получал ответа (`DNS_PROBE_STARTED` у vk.ru).

Уже отвергнуто: DoH для этих имён (ya.ru: сброс соединения), сервер имён с `detour: direct` (sing-box не запускается: «detour to an empty direct outbound makes no sense»).

## Решение

1. Новый сервер имён `direct-dns`: обычный UDP-DNS `77.88.8.8` (Яндекс) БЕЗ `detour`. Запрос идёт прямым выходом через физический адаптер (`auto_detect_interface`), мимо туннеля и мимо системного резолвера. Выбор: UDP не даёт сброса соединения, как DoH; без `detour` ядро принимает конфигурацию; Яндекс-DNS возвращает «российские» адреса для российских сайтов.
2. На `direct-dns` отправляются имена: суффиксы пресета «Российские сайты напрямую», прямые домены пользователя и имена, которые запрашивают прямые приложения (DNS-правило по `process_name`). Остальное по-прежнему через DNS VPN.
3. Маршрут: приложения напрямую (правило `process_name`, `find_process`), затем домены, затем пресеты, затем итоговый `proxy`; порядок: sniff, перехват DNS, адрес сервера, локальные адреса, приложения, домены, пресеты.
4. `set_rules` при включённом VPN переподключает ядро с новыми правилами (как смена области): один затвор, состояние «Переключаем…», при ошибке возвращаются прежние правила и показывается «Не удалось применить исключения. Работают прежние». При выключенном VPN правила только запоминаются, ничего не запускается.

## Последствия

- Если провайдер подменяет или блокирует UDP на 53-й порт, прямые сайты не откроются; запасной вариант — другой адрес в `DIRECT_DNS_ADDRESS`.
- Список сайтов пресета не менялся.
- Проверку `sing-box check` выполняет CI (`vpn-config-check`); результат реальной работы на Windows проверяет владелец.
