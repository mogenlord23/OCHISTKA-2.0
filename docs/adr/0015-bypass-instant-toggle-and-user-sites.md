# ADR 0015: мгновенная кнопка обхода, откат по скорости и сайты пользователя

- **Дата:** 2026-11-21
- **Статус:** принято автономно (владелец недоступен), проверка на Windows впереди
- Дополняет ADR 0014. Не меняет: один объединённый пресет, одна кнопка, 120 с, без автозапуска, взаимное исключение с VPN, Claude только через VPN, Telegram/Steam/Riot исключены, 135 закреплённых файлов, `Universal V13 Lite.txt`.

## Контекст
Проверка fba6b96 на Windows: ~10 с до «Включено», через ~2 с обход сам выключился (откат по скорости). Владелец хочет мгновенную кнопку, обход без выдуманных ожиданий и без отката от разброса, и панель для своих сайтов.

## Решения
1. **Мгновенная кнопка.** Переключатель меняется в тот же кадр (желаемое положение хранится в интерфейсе), надпись «Включаем…»/«Выключаем…»; запуск, остановка и проверки идут в Rust в фоне (`spawn_blocking`). Не удалось — переключатель возвращается назад с короткой причиной. «Включено» показывается только по подтверждённому состоянию Rust. Честно: движок за мгновение не стартует; реальное время пишется в `desync-start.log`.
2. **Критический путь.** Замер без обхода идёт параллельно с подготовкой файлов (лимит 3 с, свежий результат ≤ 5 мин берётся повторно); проверка SHA-256 встроенных файлов — один раз при старте программы в фоне, затем по размеру и времени изменения файла (изменение сбрасывает запись; перед запуском проверка остаётся); ожидание после запуска процесса 400 мс вместо 1 с. Цифры — `docs/status/bypass-optimization.md`.
3. **Откат по скорости только при подтверждении.** Замедление считается, если «в 1,5 раза и не меньше 1 с» либо «на 5 с и больше» (порог шума поднят с 250 мс до 1 с: 400 → 650 мс больше не повод). Откат только если замедление подтвердил повторный замер через 5 с на том же адресе; адрес, переставший открываться, откатывает только при повторном отказе. Адрес, не открывавшийся без обхода, не сравнивается. Причина показывается словами с названиями сайтов и секундами; каждый замер пишется в `desync-speed.log`. «Функционально подтверждено» остаётся `false`.
4. **Разгрузка пресета.** Убираются только доказуемо недостижимые секции (перекрыты более ранней: движок берёт первую совпавшую). Остальное остаётся. 145 → 133 секции. Отчёт — `docs/status/bypass-slim-report.md`.
5. **Сайты пользователя.** Кнопка сбоку («Сайты» рядом с переключателем) выдвигает панель (220 мс, без прыжков; без анимации при `prefers-reduced-motion`). Принимаются домены и https-ссылки (берётся домен); IP-адреса, порты, логины, `http://`, не-ASCII отклоняются фразой «Введите адрес сайта, например example.com»; максимум 200, повторы убираются, один плохой адрес отклоняет весь ввод. Хранение — `user-sites.json` в папке данных обхода, только домены. **Применение — при следующем включении** (не «сразу»): список записывается в `lists/nz-user-sites.txt` в папке движка, к аргументам запуска добавляется одна последняя секция с тем же рецептом, что у «Выбрано вручную» в пресете; «сразу» потребовало бы перезапуска работающего движка и повторных проверок, а риск неверного состояния выше пользы. Секция последняя: ловит только то, что не поймали более ранние.
6. **Тексты без технических слов** (замер, базовый, служба, порт, драйвер, SHA, пресет, движок): тесты Rust и Vitest; единственное исключение — «Драйвер не остановлен, перезагрузите компьютер». Подробности ошибок идут в журналы, а не в интерфейс.

## Последствия
- Откат по скорости станет редким и объяснимым; цена — до ~5 с дольше держится обход, который реально хуже.
- Добавленные сайты не меняют длину командной строки (список в файле): запас до предела Windows сохраняется (тест).
- Не проверено на Windows: мгновенность в окне, реальные замеры, остановка службы, работа обхода у провайдера, вид панели (скриншот с f15de11 в облаке не сравнивался).
