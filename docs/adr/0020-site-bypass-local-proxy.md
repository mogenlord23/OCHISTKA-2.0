# ADR 0020: «Обход сайтов» — локальный прокси без драйверов

- **Дата:** 2026-11-22. **Статус:** решение владельца. После ADR 0019.

## Решение

1. Одна кнопка «Обход сайтов». Включение: локальный прокси на 127.0.0.1 (HTTP CONNECT, обычный HTTP через прокси и SOCKS5 без пароля) и системный прокси на него. Выключение: прокси остановлен, прежний системный прокси возвращён.
2. Для TLS-соединений на порт 443 к сайтам из списка первый пакет ClientHello уходит двумя частями; разрез внутри имени сайта (SNI), так что имя целиком не оказывается ни в одной части. Остальной трафик не меняется.
3. Список: `assets/sites/builtin.txt` + пользовательский из панели «Сайты». Совпадает домен и поддомены.
4. Крейт `crates/proxy-bypass` — только стандартная библиотека (потоки, без tokio). Драйверов, перехвата пакетов, внешних программ и прав администратора нет.
5. Прежние значения системного прокси пишутся в `%LOCALAPPDATA%\OCHISTKA\desync\proxy-backup.txt` до изменения. Выключение и запуск программы возвращают их; если вернуть не удалось — «Ошибка», файл остаётся для повтора.
6. Системный прокси: Windows — `HKCU\...\Internet Settings` (ProxyEnable, ProxyServer) + InternetSetOption; macOS — `networksetup` (может запросить пароль); Linux — только GNOME через `gsettings`, остальные окружения «не поддерживается».
7. Взаимное исключение с VPN прежним механизмом (`NetCoordinator`, охрана включения VPN): включение обхода выключает VPN, включение VPN выключает обход.
8. Пока обход выключен, потоков и таймеров нет; интерфейс один раз читает состояние при открытии вкладки, без опроса.

## Не проверено

- Работа у провайдера (YouTube, Discord, X) и то, что одного разреза ClientHello достаточно.
- Реальное изменение системного прокси на Windows, macOS (запрос пароля) и разных окружениях Linux.
- QUIC/UDP (прокси его не обрабатывает) и приложения, не использующие системный прокси.
- Браузеры, у которых свой прокси или DNS-over-HTTPS.
