# ADR 0013: управление службами через sc.exe

- **Дата:** 2026-11-19
- **Статус:** принято (круг 4, этап S2)

## Контекст

Раздел «Процессы / Службы» был только для чтения и без состояния. Нужны запуск, остановка и смена типа запуска (авто / вручную / отключена), с фактическим состоянием и результатом, без `unsafe` вне `win32_ffi.rs`.

## Решение

1. **Механизм: `C:\Windows\System32\sc.exe` по абсолютному пути** (папка Windows из `SystemRoot`), без поиска по PATH, без окна, с ограничением 20 секунд (по истечении процесс убивается). Состояния читаются из `sc query type= service state= all`, типы запуска и отложенный автозапуск из реестра `HKLM\SYSTEM\CurrentControlSet\Services` (`winreg`).
2. **Почему не `windows-service`:** крейт нужен для написания служб; перечисления служб в нём нет (`EnumServicesStatusEx`). Свой FFI к SCM дал бы `unsafe` без выгоды по сравнению с `sc.exe`.
3. **Разбор вывода не зависит от языка Windows.** Подписи строк `sc` переведены (на русской Windows «ИМЯ_СЛУЖБЫ», «СОСТОЯНИЕ»), но слова состояния (`RUNNING`, `STOPPED`...) и числа нет. Разбор опирается на строение: первая строка блока даёт имя, строка с числом и словом состояния даёт состояние. Результат действий определяется кодом выхода (5, 1051, 1058, 1060 ...) и повторным чтением: после `start` и `stop` ждём нужное состояние до 10 секунд, после `config` перечитываем реестр. Ложного успеха нет: «не изменилось» это ошибка.
4. **Защита (ядро, `ochistka_core::services`):** чёрный список критичных служб (RPC, DCOM, Defender, брандмауэр, шифрование, планировщик, WMI, профили, питание и др.) никогда не меняется, даже с подтверждением. Служба с последствиями (печать, обновления, звук, Wi-Fi, Bluetooth, поиск и др.) останавливается или отключается только после явного подтверждения с текстом последствий. Имя службы проверяется (буквы, цифры, `_ . - $ @`), чтобы в `sc` не попали опции. Подтверждение проверяет бэкенд, не только интерфейс.
5. **Откат:** перед первой сменой типа запуска прежний тип сохраняется в `HKCU\Software\OCHISTKA\ServiceStartBackup`; кнопка «Вернуть: …» возвращает его и стирает запись. Повторные смены не затирают самое первое значение. При неудаче запись удаляется.
6. **Права администратора:** действие требует прав (иначе SCM отвечает «отказано в доступе»). **Повышение прав на одно действие (отдельный запуск с UAC) в этом этапе не реализовано**, как и в S1. Если OCHISTKA запущена без прав, список виден, а запуск, остановка и смена типа выключены с понятной причиной на странице. Признак прав: открытие ключа служб на запись (ничего не меняет). Добавить отдельный повышенный помощник можно позже.
7. Состояние служб перечитывается раз в 6 секунд, пока открыт подраздел и нет действий в работе.

## Последствия

Порт `ServiceBackend` (ядро) с поддельной реализацией в тестах: чёрный список, разбор `sc`, коды ошибок, типы запуска, откат, проверка результата. Реализация Windows в `crates/platform/src/windows/services.rs`, заглушки Linux и macOS возвращают `Unsupported`. Не проверено на реальной Windows: `sc.exe` отвечает на разных языках и сборках как описано; список чёрного списка стоит просмотреть на практике.
