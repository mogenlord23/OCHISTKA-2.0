# 0009. Оформление: реальные действия в Windows

Дата: 2026-11-18

## Решение

- Акцентный цвет, прозрачность, заливка Пуска, тёмная и светлая тема меняются записью в HKCU через `winreg` (безопасная обёртка). Обои — крейт `wallpaper`. Весь unsafe остаётся только в `clamav_ffi.rs`.
- Логика в `ochistka-core::appearance` за портами `RegistryPort` и `WallpaperPort`; тесты идут на поддельном реестре. Реальные записи только под `cfg(windows)`.
- Перед первым изменением прежние значения копируются в `HKCU\Software\OCHISTKA\Backup\Appearance` (отсутствующие значения помечаются `.absent`). Копия не перезаписывается; «Вернуть оформление Windows» возвращает её. Прежние обои запоминаются один раз и возвращаются кнопкой «Вернуть прежний фон».
- Каждое изменение требует диалога подтверждения и `confirmed: true` в команде.
- «Режим для Пуска» меняет только `SystemUsesLightTheme`; «Тёмный/Светлый режим» — и приложения, и систему.
- Плитки встроенных обоев меняют только фон предпросмотра в приложении (превью низкого разрешения). Курсор плитки становится указателем самого приложения через CSS `cursor: url(data:image/svg+xml…)`; Windows не меняется.

## Ограничения

Сообщение WM_SETTINGCHANGE не рассылается (потребовало бы unsafe): часть оболочки подхватит тему после перезапуска проводника или входа в систему.
