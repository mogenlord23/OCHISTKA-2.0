# ADR 0004: собственный движок обнаружения на YARA-X вместо ClamAV

- **Дата:** 2026-11-18
- **Статус:** предложено (код не писать до подтверждения владельцем)
- **Заменяет:** ADR 0002 в части движка (ClamAV). Эвристика из ADR 0002 (пункт 4) и правило карантина (пункт 5) остаются.

## Контекст

ADR 0002 выбрал ClamAV и вызов `clamscan.exe` как внешней программы. При разборе по коду (аудит 2026-11-18) выяснилось:

- ClamAV тянет GPL-2.0 бинарники в установщик, `freshclam` и базы сигнатур обновляются отдельным процессом, а пути к движку и базам требуют отдельной проверки подлинности.
- Разбор текстового вывода `clamscan` дал класс находок, которые нельзя надёжно отличить от подделки (аудит, группа «clamscan»).
- Владелец решил не использовать ClamAV (решение D7, 2026-11-18). Все находки, связанные с его интеграцией, закрыты как `wontfix` по этому ADR.

Нужен движок, который:

1. работает как библиотека внутри приложения, без внешних программ и без PATH-поиска;
2. распространяется под лицензией, совместимой с установщиком;
3. работает полностью локально (файлы пользователя не уходят наружу, см. ADR 0002);
4. поддерживает лимиты времени и размера, которые задаёт решение D18.

## Решение (предлагается)

1. **Движок — YARA-X** (крейт `yara-x`, Rust-реализация YARA от VirusTotal). Лицензия BSD-3-Clause по агрегаторам; **до внедрения проверить файл LICENSE в репозитории и версию на crates.io** (в этой сессии прямой доступ к crates.io не проверялся).
2. **Граница.** В `ochistka-core` добавляется порт `VirusScanPort` (он уже есть для ClamAV). Адаптер живёт в `crates/platform/src/windows/` (по правилам CLAUDE.md системный код только в `crates/platform`). Интерфейс получает результат через Tauri-команду, как сейчас.
3. **Правила.** В дистрибутив попадают только правила с лицензией, которая разрешает распространение, и файл лицензии рядом с каждым набором в `rules/`. Чужие наборы правил включаются отдельным решением владельца, потому что это обязательства по лицензии. На этом этапе набор правил минимальный и собственный.
4. **Лимиты.** Из решения D18: один скан за раз, отмена, таймаут на проход, максимальный размер файла (200 МБ). Таймаут на файл задаётся настройкой движка, если она есть в API крейта (проверить по документации крейта).
5. **Эвристика** (ADR 0002, пункт 4) остаётся подсказкой и не удаляет файлы.
6. **Обновления правил** в этом ADR не описываются. Обновления через подписанные пакеты будут отдельным ADR.
7. **Карантин** (решение D8) делается после принятия этого ADR, отдельным ADR 0005.
8. **Удаление клам-пути:** адаптер `windows/clamav.rs` и связанные тесты удаляются, когда адаптер YARA-X пройдёт тесты и проверку на Windows. До этого оба адаптера могут стоять за портом.

## Последствия

- ADR 0002 частично заменён этим ADR (движок). Пункты 4–6 ADR 0002 сохраняются.
- В установщике нет внешних исполняемых файлов антивируса. Лицензии клам-бинарников больше не нужны.
- **Качество обнаружения ниже, чем у ClamAV с его базой сигнатур.** Наборы правил надо писать и проверять самим. Это риск ложных срабатываний и пропусков; его нельзя закрыть кодом, только тестовыми наборами файлов.
- Нужна проверка на Windows: сборка, работа с путями, таймауты, поведение на большом файле.
- Существующие закрытые `wontfix` находки ClamAV (D7) остаются закрытыми: ими занимается этот ADR.

## Что нельзя откатить легко

- Решение, какие чужие наборы правил включаются в дистрибутив (обязательства лицензии и доверие пользователей).
- Удаление адаптера ClamAV. Технически откатывается через git, но тогда это повторный выбор движка.

## Открытые вопросы владельца

2. Нужны ли вообще чужие наборы правил в дистрибутиве на этом этапе, или только собственные?
3. Лимиты D18 (200 МБ на файл, 10 минут на проход) — подходят?
