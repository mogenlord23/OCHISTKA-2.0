# ADR 0011: драйверы по производителям, без переключателя ОС, установка официальным установщиком

- **Дата:** 2026-11-19
- **Статус:** принято; заменяет пункт 1 («Сверху раздела — переключатель ОС») в ADR 0003 и строку «Сверху переключатель ОС» в CLAUDE.md. Остальные пункты ADR 0003 остаются в силе.

## Контекст

OCHISTKA это exe для Windows. Переключатель «Windows / macOS / Linux» на странице «Компьютер → Драйверы» ничего не давал: две из трёх кнопок были выключены. Владелец просит страницу как в первом приложении (0.5.5): плитки по производителям, фильтр по клику, кнопка установки.

## Как работало в 0.5.5 (по исходникам `DriverCatalog.cs`, `DriversView.cs`, `OfficialInstallers.cs`)

- Каталог из ~25 карточек (NVIDIA, AMD, Intel, Realtek, Bluetooth/Wi-Fi, USB, ASUS, MSI, GIGABYTE, Lenovo, Dell, HP, Acer, Surface, Logitech). Плитки производителей сверху фильтровали каталог.
- У четырёх карточек (NVIDIA App, AMD Software, Intel DSA, Intel Wi-Fi) был прямой установщик: загрузка по https в папку приложения, лимит 512 МБ, проверка Authenticode через PowerShell (статус Valid и имя издателя в Subject), затем запуск установщика. У остальных кнопка открывала официальную страницу производителя.
- Отдельно: поиск драйверов через Windows Update (COM `Microsoft.Update.Session`) и установка INF через `pnputil /add-driver`.

## Решение

1. **Переключатель ОС убран из интерфейса.** Страница показывает драйверы Windows. Архитектура платформ не меняется: адаптеры для macOS и Linux остаются заглушками `Unsupported` (`DriverHost` в `crates/platform/src/{linux,macos}/drivers.rs`).
2. **Каталог живёт в ядре** (`ochistka_core::drivers::CATALOG`), интерфейс получает его командой `drivers_catalog` без адресов и передаёт только `id`. Плитки: NVIDIA, AMD, Intel, Realtek, Wi-Fi / Bluetooth, USB, Производители ПК. Найденный в этом компьютере производитель идёт первым с пометкой «ваше устройство» (по видеокартам, процессору и плате из `get_hardware`).
3. **Кнопка «Установить»** (широкая, по центру карточки) скачивает официальный установщик: только https, только домены из белого списка (`nvidia.com`, `intel.com`, `amd.com`, `realtek.com` и их поддомены), без логина и порта в адресе; каждая переадресация проверяется тем же правилом; страница вместо файла отклоняется; лимит 512 МБ; файл в `%LOCALAPPDATA%\OCHISTKA\Downloads`, сначала `.part`. Затем `Get-AuthenticodeSignature` через `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe` (путь к файлу передаётся переменной окружения, не текстом скрипта): статус обязан быть `Valid`, а CN или O сертификата равен имени издателя из каталога (точное совпадение, не «содержит»). Непроверенный файл удаляется. После проверки установщик запускается через `explorer.exe`: UAC запрашивается только для него.
4. **Нет прямой ссылки** → кнопка «Открыть сайт» открывает официальную страницу в браузере по умолчанию. Для AMD так сделано намеренно: прямую ссылку 0.5.5 сервер `drivers.amd.com` отдаёт только при заголовке Referer со страницы amd.com (без него перенаправляет на страницу «загрузка не завершена»); подделывать заголовок мы не стали.
5. **Windows Update:** для пунктов, где драйвер может поставить Windows, есть вторая кнопка «Установить через Windows Update», она открывает `ms-settings:windowsupdate-optionalupdates`.
6. Состояния кнопки: «Установить» / «Открыть сайт», «Загрузка N%» (заливка), «Проверка подписи…», «Запуск установщика…», «Установщик запущен», «Повторить» с причиной под кнопкой. Одновременно идёт одна установка.
7. Логотипы NVIDIA, AMD, Intel, Bluetooth из simple-icons (CC0-1.0), для Realtek и USB знака там нет: буквенная метка. См. `THIRD-PARTY.md`.

## Последствия

- Список установленных драйверов (INF, `pnputil /enum-drivers`) в текущей странице не было и не добавлялось; остаётся `planned`.
- Версии в адресах установщиков (NVIDIA App 11.0.9.565, Intel Wi-Fi 24.80.0) устаревают; тогда загрузка завершится ошибкой, а карточка потребует обновления адреса в каталоге. Подпись всё равно проверяется.
- Не проверено на Windows: запуск через `explorer.exe`, UAC, фактическая подпись установщиков Intel (допустимое имя издателя «Intel Corporation» взято по обычной практике), работа `native-tls` (Schannel).
