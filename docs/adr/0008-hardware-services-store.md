# ADR 0008: комплектующие, службы и пакеты Store (только чтение)

- **Дата:** 2026-11-18
- **Статус:** принято
- **Дополняет:** ADR 0006 (программы только для чтения).

## Решение

1. **GPU и материнская плата через sysinfo 0.40.4.** Крейт отдаёт `Gpus` и `Motherboard` на Windows (проверено по исходникам в реестре крейтов). Порт `HardwarePort` живёт в `ochistka-core/src/hardware.rs`; адаптер — в `crates/platform/src/windows/hardware.rs`. Серийные номера не читаем. На Linux и macOS — `Unsupported` с причиной «Чтение комплектующих недоступно на <ОС>».
2. **Службы — из реестра, не через SCM.** Список берём из `HKLM\SYSTEM\CurrentControlSet\Services` через `winreg` (безопасная обёртка, уже в проекте). Показываем имя, отображаемое имя и режим запуска. Состояние «работает/остановлена» требует `EnumServicesStatusEx` (FFI), поэтому пока не показывается. Собственного `unsafe` нет. Крейт `windows-services` (Microsoft) для этого не подходит: он для реализации службы, а не для перечисления. `windows-service` 0.8.1 перечисления не имеет.
3. **Store — реестр пакетов, только чтение.** Источники: `HKCU\Software\Classes\Local Settings\...\AppModel\Repository\Packages` (без прав администратора) и `HKLM\...\Appx\PackageRepository\Packages`. Имя и версия берутся из имени пакета (`Имя_Версия_Архитектура__издатель`). Фреймворки и ресурсные пакеты пропускаем. Ссылки `ms-resource:` и `@...` в отображаемом имени заменяем именем пакета. Пути в реестре Store не проверены на реальной Windows: статус `implemented`.
4. **VPN: base64 и vmess.** Тело подписки, которое целиком закодировано base64 (с паддингом или без, в том числе url-safe), декодируется, если внутри видны ссылки `scheme://`. Имя сервера vmess берётся из поля `ps` JSON; без него — из фрагмента `#`. Функции чистые, покрыты тестами в `apps/desktop/src/lib/vpn.ts`.

## Что не сделано

- Состояние службы (работает/остановлена) и действия над службами.
- Проверка всех путей и полей на реальной Windows: статус `implemented`, не `verified`.
