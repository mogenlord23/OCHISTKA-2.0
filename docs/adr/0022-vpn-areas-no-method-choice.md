# ADR 0022: области VPN, без выбора способа

- **Дата:** 2026-11-22. **Статус:** решение владельца. Уточняет ADR 0021 (три режима → две области).

## Решение

1. В интерфейсе нет выбора «системный прокси» и «TUN»: пользователь выбирает только область и включает VPN.
2. Режима «Напрямую» нет: VPN выключен = всё напрямую. Включить VPN можно в любой области (раньше «Напрямую» не давал включить).
3. Две области, одна выбрана, одна обводка:
   - «Весь компьютер» — все приложения и сайты через VPN. Туннель TUN (sing-box) без системного прокси; в конфигурации ядра: вход TUN (адрес `172.19.0.1/30`, автомаршрут), перехват DNS, локальные адреса напрямую, исключения пользователя прежние.
   - «Только нужные сайты» — через VPN только сайты из панели «Сайты», остальное (включая российские сервисы) напрямую. Подпись: «Российские сервисы работают как обычно». Работает через локальный вход ядра и системный прокси (как раньше), права администратора не нужны.
4. Область по умолчанию — «Только нужные сайты». Старое сохранённое значение `direct` читается как она.
5. Переключатель «Включить VPN» меняется мгновенно (включается/выключается в тот же кадр), при ошибке возвращается, причина — одна короткая строка. Смена области при включённом VPN — переподключение.
6. Тексты без слов «системный прокси», «TUN», «маршрут», «порт», «драйвер», «движок», «SHA».

## Права администратора (открыто, нужно решение)

Туннель TUN создаёт сетевой адаптер: на Windows нужны права администратора. Сейчас приложение их ни разу не запрашивает (раньше VPN работал только через системный прокси, без прав). Поэтому «Весь компьютер» без прав отказывает сразу и коротко: «Для всего компьютера нужны права администратора», ничего не меняя. «Только нужные сайты» права не требует. Как получить права один раз (при установке или при первом включении) — решение владельца ещё не принято; запрашивать при каждом включении не будем. Вариант, который уже проверялся в CI на Windows (этап 12): служба, регистрируемая установщиком один раз.

## Не проверено

- Реальный туннель TUN на Windows: создание адаптера, нужен ли отдельный файл адаптера рядом с ядром (в закреплённой сборке ядра он не поставляется — не подтверждено), работа DNS.
- Поведение при смене области на живом соединении (проверено только на заглушках).
- Linux и macOS: логика одинаковая, ядро запускается только на Windows.
