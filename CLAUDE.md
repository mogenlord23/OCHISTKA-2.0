# OCHISTKA v1: инструкции для Claude Code

Этот файл читается в начале каждой сессии. Соблюдай его, если пользователь не попросил иное.

## Цель

Кроссплатформенная утилита для обслуживания компьютера: очистка, программы, процессы, сеть, безопасность (собственный антивирус), виджеты, оптимизация, драйверы, настройки.

Текущий этап: **только Windows 10/11 x64**. macOS и Linux не реализуем, но архитектура должна позволить добавить их без переписывания интерфейса и ядра.

## Стек

- Tauri 2 (оболочка), Rust (ядро и системные операции), Svelte 5 + TypeScript (интерфейс), Vite.
- Структура: `apps/desktop` (Tauri и интерфейс), `crates/ochistka-core` (бизнес-логика без UI), `crates/platform` (системные адаптеры по ОС).
- Системный код живёт только в `crates/platform`, за трейтами. Внутри него — модули `windows/`, `macos/`, `linux/`. Модули для других ОС пока пустые заглушки, которые возвращают `Unsupported`.
- Интерфейс не вызывает системные команды напрямую. Только типизированные Tauri-команды.
- Проверки: `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`, `svelte-check`, `vitest`, Prettier.
- GitHub Actions не используем. Аналитику (PostHog и подобные) и отправку диагностики не добавляем.

## Правила безопасности

- Удаление всегда через карантин: сначала файл переносится в карантин, окончательное удаление только по отдельному подтверждению пользователя.
- Системные папки и пути вне белого списка не удаляем никогда.
- Каждая системная настройка (буст, питание, автозагрузка, фаервол) записывает прежнее значение и может быть откатана.
- Команды запускаются с абсолютными путями к системным утилитам, без поиска по PATH.
- Права администратора запрашиваются только для конкретного действия, а не для всего приложения.

## Правила работы

- Старый код (WPF, ветка `migration/tauri-rust` в репозитории `mogenlord23/OCHISTKA`) используется только как справка по поведению. Код оттуда не копируем.
- Перед кодом: короткий план (до 5 пунктов, навык /ochistka-feature), затем тесты (TDD), затем реализация. Ручные навыки: /ochistka-feature, /ochistka-ui, /ochistka-security, /ochistka-vpn, /ochistka-verify. Вызывать по конкретной задаче.
- Каждая функция имеет тесты. Изменения маленькие, с понятными сообщениями коммитов (Conventional Commits).
- Для каждой функции ведётся статус по ОС: `implemented`, `verified` (проверено на реальной ОС), `planned`. Не писать «работает», если не проверено на этой ОС.
- Недоступная на текущей ОС функция показывается в интерфейсе выключенной, с причиной.
- Если проверка невозможна в текущем окружении (например, Windows-GUI из Linux), так и писать в отчёте.

## Разделы интерфейса (семь)

Навигация — правая панель с иконками. Окно без системной рамки: собственные кнопки свернуть, развернуть и закрыть. Внутри каждого раздела — подразделы (вкладки на странице).

1. **VPN** — подразделы: Подписка и импорт, Серверы, Маршруты и исключения. Открывается первым.
2. **Вирусы** — подразделы: Проверка, Находки, Журнал проверки.
3. **Процессы** — подразделы: Процессы, Службы.
4. **Программы** — подразделы уточняются.
5. **Диски** — подразделы уточняются.
6. **Компьютер** — подразделы: Комплектующие и графики, Настройки, Boost, Драйверы. Сведения о CPU, GPU, RAM и дисках — здесь.
7. **Оформление** — подразделы уточняются.

Очистка, Оптимизация, Сеть, Виджеты и Настройки из прежнего списка пока не распределены по семи разделам; их место уточняется.

## Антивирус (окончательное решение пользователя, не менять)
- Один продукт: libclamav собирается из исходников ClamAV (GitHub) и встраивается в приложение. Отдельного clamscan.exe и отдельной установки нет. unsafe только в одном FFI-модуле, снаружи безопасный трейт VirusScanPort. Сигнатуры не вшиваются, обновляются отдельно.
- Свой слой поверх: инвентаризация (тип файла по заголовку, без запуска), эвристика с причинами, ИИ-слой (локальная ONNX-модель; пока интерфейс и заглушка), итоговая оценка с объяснением. ИИ только повышает подозрение, удаляет пользователь.
- Карантин: перенос, манифест (путь, SHA-256, дата, причина), восстановление, окончательное удаление по подтверждению.
- YARA-X и Microsoft Defender не используем. Последствия GPL-2.0 — в THIRD-PARTY.md, лицензия OCHISTKA — TBD.

## Драйверы (подраздел «Компьютер»)

- Переключателя ОС в интерфейсе нет (ADR 0011, заменяет ADR 0003 п. 1). Плитки по производителям; установка официальным установщиком производителя (https, белый список доменов, проверка подписи) или через Windows Update.
- На macOS и Linux в будущем: только инвентаризация и обновления через системные инструменты.

## Режим работы
- Пользователь не программист. Технических вопросов не задавай: принимай разумное решение, записывай в docs/adr/ и продолжай. Останавливайся только перед действием, которое меняет или удаляет что-то на компьютере пользователя вне тестов.
- Работай по docs/PLAN.md сверху вниз, отмечай [x]. Если прервался — продолжай с первого невыполненного.
- Чего не хватает (скриншоты, цвет, картинка) — не жди, ставь разумный вариант, записывай в docs/status/ и иди дальше.
## Экономия токенов
- Читай только нужные файлы. Тесты точечно и тихо (cargo test -p <крейт> -q, vitest --reporter=dot). Полный набор — в конце этапа. Аудит и тяжёлые скиллы не запускай. Длинный вывод не показывай.

## Предпочтения владельца (общие правила интерфейса)
- Одно скругление во всём приложении, только из токенов. Окно скруглено сильно, без тени, как в f15de11.
- Никаких подтверждающих окон в обычных действиях; выбор мгновенный (обводка в тот же кадр); повторное нажатие снимает выбор и возвращает прежнее состояние.
- Все флажки — один компонент Check.svelte; все выбираемые плитки — одной обводкой.
- Пользователю не показывать технические слова и коды; всё делается без ручных команд.
- Вид раздела менять только после сравнения скриншота с версией f15de11. Подробности: docs/REQUIREMENTS.md, docs/PROMPT-round3.md.
- Помощники (субагенты) только при необходимости и не больше одного одновременно. Основная модель — Sonnet.
