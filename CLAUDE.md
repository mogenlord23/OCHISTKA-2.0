# OCHISTKA v1: инструкции для Claude Code

Этот файл читается в начале каждой сессии. Соблюдай его, если пользователь не попросил иное.

## Цель

Кроссплатформенная утилита для обслуживания компьютера: очистка, программы, процессы, сеть, безопасность (собственный антивирус), виджеты, оптимизация, драйверы, настройки.

Текущий этап: **только Windows 10/11 x64**. macOS и Linux не реализуем, но архитектура должна позволить добавить их без переписывания интерфейса и ядра.

## Стек

- Tauri 2 (оболочка), Rust (ядро и системные операции), Svelte 5 + TypeScript (интерфейс), Vite.
- Структура: `apps/desktop` (Tauri и интерфейс), `crates/ochistka-core` (бизнес-логика без UI), `crates/platform` (системные адаптеры по ОС).
- Системный код живёт только в `crates/platform`, за трейтами. Внутри него — модули `windows/`, `macos/`, `linux/`. Модули для других ОС пока пустые заглушки, которые возвращают `Unsupported`.
- Интерфейс не вызывает системные команды напрямую. Только типизированные Tauri-команды.
- Проверки: `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`, `svelte-check`, `vitest`, Prettier.
- GitHub Actions не используем. Аналитику (PostHog и подобные) и отправку диагностики не добавляем.

## Правила безопасности

- Удаление всегда через карантин: сначала файл переносится в карантин, окончательное удаление только по отдельному подтверждению пользователя.
- Системные папки и пути вне белого списка не удаляем никогда.
- Каждая системная настройка (буст, питание, автозагрузка, фаервол) записывает прежнее значение и может быть откатана.
- Команды запускаются с абсолютными путями к системным утилитам, без поиска по PATH.
- Права администратора запрашиваются только для конкретного действия, а не для всего приложения.

## Правила работы

- Старый код (WPF, ветка `migration/tauri-rust` в репозитории `mogenlord23/OCHISTKA`) используется только как справка по поведению. Код оттуда не копируем.
- Перед кодом: план (superpowers:writing-plans), затем тесты (TDD), затем реализация.
- Каждая функция имеет тесты. Изменения маленькие, с понятными сообщениями коммитов (Conventional Commits).
- Для каждой функции ведётся статус по ОС: `implemented`, `verified` (проверено на реальной ОС), `planned`. Не писать «работает», если не проверено на этой ОС.
- Недоступная на текущей ОС функция показывается в интерфейсе выключенной, с причиной.
- Если проверка невозможна в текущем окружении (например, Windows-GUI из Linux), так и писать в отчёте.

## Разделы интерфейса (семь)

Навигация — правая панель. Внутри каждого раздела — подразделы (вкладки на странице).

1. **Вирусы** — подразделы: Проверка, Находки, Журнал проверки.
2. **VPN** — подразделы: Подписка и импорт, Серверы, Маршруты и исключения.
3. **Процессы** — подразделы: Процессы, Службы.
4. **Программы** — подразделы уточняются.
5. **Диски** — подразделы уточняются.
6. **Компьютер** — подразделы: Комплектующие и графики, Настройки, Boost, Драйверы. Сведения о CPU, GPU, RAM и дисках — здесь.
7. **Оформление** — подразделы уточняются.

Очистка, Оптимизация, Сеть, Виджеты и Настройки из прежнего списка пока не распределены по семи разделам; их место уточняется.

## Антивирус

- Раздел «Вирусы», первый в навигации. Подразделы: Проверка (запуск с анимацией), Находки (выбор элементов, кнопка «Удалить» через карантин), Журнал проверки.
- Движок: ClamAV (GPL-2.0). Вызов `clamscan.exe` по абсолютному пути из папки установки. Обновление баз — `freshclam`. Библиотеку `libclamav` не используем. Решение зафиксировано в `docs/adr/0002-antivirus.md`.
- Нейросеть на этом этапе — эвристическая оценка подозрительных файлов (имя, двойное расширение, исполняемый файл в загрузках, размер). Она только подсказывает. ONNX-модель подключим позже, когда будет выбрана модель с понятной лицензией. ИИ не удаляет файлы сам.
- Microsoft Defender не используем и не управляем им.

## Драйверы (подраздел «Компьютер»)

- Сверху переключатель ОС. На Windows: список драйверов из Windows (INF и Windows Update). Установка только через системные механизмы.
- На macOS и Linux в будущем: только инвентаризация и обновления через системные инструменты.
